## 1. 결재함

### 1.1 구조 (코더와 합의, #25)

| 화면 | 내용 |
|---|---|
| 목록 | 탭 “대기 N / 처리됨”. 카드 = 종류 배지 · 날짜 / 이슈 제목 / 요청 에이전트(이름 · 역할, 에이전트 색) · 파일철(저장소 #이슈). 오래된 것부터. 처리됨 카드엔 `✅ 결과` |
| 한 건 | ← 목록 / 종류 배지 / 제목 / 요청 에이전트 · 파일철(GitHub 원문 ↗) · 날짜 / 내용 / 선택지 / 추천 이유(접힘) / 의견 / [나중에] [결재] |
| 결재 직후 | 고른 선택지 위에 결재 도장 → “#이슈에 ✅ 결재 댓글을 남겼어요” → 1.2초 뒤 다음 건(없으면 목록) |
| 방문자 | “결재 대기 N건” + SECRET 표지 목록(종류 · 요청 에이전트 · 날짜만). 내용 · 선택지 · 이슈 제목 없음 |
| 로그인 입구 | 출입문 화면 오른쪽 아래 구석 열쇠 점(평소 25% 밝기, 호버·초점이면 청록) + `?owner`. 로그인되면 HUD에 `OWNER` 꼬리표 |

- 패널: 3D 사무실 위 오른쪽, 폭 440px(`--approval-panel-w`). 640px 이하에서는 전체 화면이다.
- 클래스는 #25의 `.approval-box`, `.approval-count`, `.approval-signin`, `.approval-list`, `.approval-item`, `.approval-reason`, `.approval-actions`를 그대로 쓰고, 탭·한 건 화면용 이름을 더했다(`.approval-tabs`, `.approval-detail`, `.approval-options`, `.approval-option`, `.approval-badge`, `.approval-stamp`, `.approval-note`).

**종류별 선택지** (서버도 같은 값을 받음, #25)

| 종류 | 선택지 | 의견 필수 |
|---|---|---|
| 결정 요청 | 요청의 선택지 N개 + “반려” | 반려 |
| 산출물 확인 | 승인 / 반려 | 반려 |
| 문서 공개 | 공개 / 고쳐서 공개 / 계속 SECRET | 고쳐서 공개 · 계속 SECRET |

의견이 필수인 선택지를 고르면 의견 라벨 뒤에 빨간 `*` 안내가 붙고, 비어 있으면 결재 버튼이 꺼진다. 서버(`needsOpinion`, #25)도 같은 규칙으로 400을 돌려준다. “고쳐서 공개”는 무엇을 고칠지 에이전트가 알아야 해서 필수다(2026-11-08, #64에서 서버 규칙에 맞춤).

| 고른 것 | 의견 라벨 안내 |
|---|---|
| 반려 | `* 반려에는 이유가 필요해요` |
| 고쳐서 공개 | `* 무엇을 고칠지 적어 주세요` |
| 계속 SECRET | `* 공개하지 않는 이유를 적어 주세요` |
| 그 밖 | `(선택)` |

“고쳐서 공개”는 반려가 아니라서 선택지 글자를 흐리게 하지 않는다(흐린 글자는 반려 · 계속 SECRET만).

### 1.2 시각 결정

- **결재는 호박 하나.** 탭, 주 버튼, 선택 표시, 배지가 모두 `--approval-accent`(호박)이다. 메모의 결재 도장(#32), 책상 방 단말기(주인의 색)와 이어진다.
- **종류는 모양으로 구분한다.** 처음에는 종류마다 색을 주려 했다. 그런데 청록·호박·라벤더가 에이전트 색(루프·메모·메시)과 같아서, 카드 하나에 “요청 에이전트 색 띠”와 “종류 색”이 겹쳤다. 그래서 색은 에이전트에만 쓰고, 종류는 아이콘 + 글자 + 배지 모양으로 나눴다.
  - 결정 요청: 갈림길 아이콘, 테두리만 있는 배지
  - 문서 공개: 문서 아이콘, 채운 배지
  - 산출물 확인: 도장 아이콘, 사선 무늬 배지. 무늬는 호박 16%, 3px 줄 + 4px 틈(주기 7px). 처음 안의 28%는 12px 픽셀 글자 획과 섞여 읽기 어려웠다(#64 앱 확인). 가장 진한 줄 위에서도 글자 대비 7.0 : 1
- 패널은 `color-scheme: dark`, `scrollbar-color: var(--bubble-dim-line) transparent`, `scrollbar-width: thin`이다. 기본 스크롤바와 textarea 손잡이가 밝게 떠 보이지 않게 한다(#64 앱 확인).
- **긴 글은 본문 글꼴로.** 라벨·배지·날짜는 갈무리(12px)를 쓴다. 제목·내용·선택지는 읽을 문장이라 `--font-text`(14~17px)로 썼다. #18 말풍선은 짧은 대사라 픽셀 폰트였지만, 결재 내용은 몇 문장이다.
- **내용은 제한된 마크다운이다**(문단 · 목록 · 굵게 · 인라인 코드 · 링크 · 표). 표는 패널 안에서 가로 스크롤한다(`tabindex=0`, `role=region`으로 키보드 스크롤 가능).
- **도장은 고른 선택지 위에.** 처음에는 제목 옆에 찍었더니 제목과 날짜를 가렸다. 고른 선택지 카드 오른쪽에 찍으니 “무엇을 결재했는지”가 도장으로 남는다.
  - 도장: 지름 88px, −12° 기울임, `--stamp-red`
  - 판 위 대비 6.3:1. 장식이기도 하지만 글자이기도 해서 대비를 맞췄다.

### 1.3 움직임

| 동작 | 기본 | 움직임 줄이기 |
|---|---|---|
| 도장 | 1.9배 크기에서 0.4초 만에 쾅(살짝 튕김), 판이 2px 눌림 | 찍힌 채로 바로 나타남(`--approval-stamp-ms: 0`) |
| 다음 건 | 도장 뒤 1.2초(`--approval-next-ms`) | 같음(읽을 시간) |

### 1.4 접근성

- **키보드만으로 결재까지 간다.** Tab → 목록 카드(버튼) → Enter → 제목에 초점 → 선택지(라디오, 화살표 키) → 의견 → Enter로 결재. Esc는 목록으로 돌아간다.
- 반려·계속 SECRET을 고르면 의견 라벨에 “* 반려에는 이유가 필요해요”가 붙는다. 의견이 비어 있으면 결재 버튼이 꺼진다. 결재를 누르면 `aria-invalid`도 켜진다.
- 결재가 끝나면 `role=status` 영역이 읽어 준다: “결재했어요: 제목 — 결과. 저장소 #이슈에 댓글을 남겼어요.”
- 보내기에 실패하면 `role=alert`로 알린다. 고른 선택지와 의견은 그대로 둔다.
- 초점 링은 청록(#18 규칙: 네온 = 누를 수 있음)이다.

### 1.6 새 항목 알림 (#240)

> 2026-11-10 · 사용자 의견: "결재함에 신규 사항이 있을 때 dot으로 띄워 주고 효과음도 넣어 줘."

**숫자 칩과 점은 뜻이 다르다**
- 숫자 칩 `대기 N`(지금)은 **남아 있는 일**이다. 결재할 때까지 그대로 있다.
- 점은 **안 본 새 일**이다. 마지막으로 결재함을 연 뒤 새로 생긴 대기 결재가 있으면 켜지고, 결재함 탭을 열면 꺼진다(브라우저 저장, 주인 · 방문자 공통).
- 그래서 둘은 함께 보일 수 있다(`대기 3` + 점 = 셋 중 새것이 있음). 대기가 0이면 점도 없다.

**점 모양**
- 지름 8 px, `--approval-accent`(호박). 바깥에 2 px 고리를 둘러(패널 · 도크 바탕색) 버튼 테두리와 떨어져 보이게 한다.
- 자리: 도크 결재함 버튼의 **비스듬히 잘린 오른쪽 위 모서리 위**다. 점 가운데를 빗변 가운데에 맞춰(대략 top −3 px · right −3 px) **반쯤 버튼 밖, 짙은 도크 바탕 위**에 놓는다. 휴대폰 아이콘 버튼(#167 340 px)도 같다. 옆 패널 탭 `결재함 N`에도 같은 점을 숫자 오른쪽 4 px에 둔다.
  - 버튼 안에 두지 않는다. 호박 버튼 위 호박 점(서재는 황갈 위 아이보리)은 바탕과 색이 같아 고리만 보이고, 빈 동그라미(라디오 버튼)로 읽힌다(#286 판정).
  - 버튼을 `clip-path`로 자르면 점이 잘리니, 점은 버튼 밖 감싸는 요소에 둔다.
- 나타남: 0.2초에 커지며(0.6 → 1배) 한 번, 그 뒤 4초마다 한 번 아주 약하게 숨 쉼(불투명도 1 → 0.6 → 1, 0.8초). 움직임 줄이기면 커지지도 숨 쉬지도 않는다.
- 색만으로 알리지 않는다: 버튼 이름에 붙인다(아래).

**글 · 화면 읽기**
- 버튼 접근 이름: `결재함, 대기 3건, 새 결재 1건`(점이 있을 때만 뒤 구절)
- 새 결재가 도착하는 순간 `aria-live="polite"` 한 번: `새 결재 1건 · 메모: 5인 책상 배치`(방문자는 제목 대신 `결재 서류`). 여러 건이 5초 안에 오면 `새 결재 3건`으로 묶어 한 번만 읽는다.

**소리**(#194, 소리 설정을 따름)
- 기본은 **주인만 듣는다.** 결재는 주인의 일이고, 방문자에게는 남의 알림 소리라 거슬린다. 방문자에게는 점과 숫자만 보인다.
- 소리 모양은 사운드 엔지니어가 정한다(제안: 책상 방 `success`보다 짧고 부드러운 두 음, 위로, 레벨 0.035, 위치 없음).
- 5초 안에 여러 건이면 한 번만 낸다. 탭이 숨겨져 있으면 내지 않고, 돌아왔을 때도 몰아서 내지 않는다(점만).

**서재에도 새 문서 점을 둔다**
- 결재함과 같은 규칙과 모양이지만 색은 **아이보리** `#f3ead8`다(결재가 아니라 읽을거리라서 호박을 쓰지 않음). 도크 서재 버튼과 탭 `서재` 옆에 둔다.
- 목록 안: 마지막으로 서재를 연 뒤 생긴(또는 갱신된) 파일철 · 문서 줄의 제목 앞에 6 px 아이보리 점. 그 문서를 열면 그 점만 꺼진다.
- 소리는 없다(서재 갱신은 잦음).

## 2. 서재 문서 뷰어

### 2.1 구조

- **왼쪽 목록**: 프로젝트 폴더(저장소 하나 = 폴더 하나, `private`는 “비공개 프로젝트” 하나로 모음) → 파일철(이슈 하나). SECRET 파일철은 방문자 목록에서 **제목도 가린다**(#25 방문자 뷰처럼 종류·날짜·참여 에이전트만).
- **오른쪽**: 파일철 머리(저장소 · 파일철 #번호 · 상태 / 제목 / 참여 에이전트) → 목차 탭(1. 기획서 → 2. 회의록 → 3. 결정 → 4. 보고서, 있는 것만) → 종이 한 장.
- **좁은 화면(≤ 760px)**: 목록이 위로 올라가고(높이 220px 스크롤), 종이가 전체 폭이 된다.
- **회의 재연에서 들어오기**: 말풍선(#18)엔 첫 문장만 나온다. “전문 보기”를 누르면 뷰어가 그 파일철의 회의록을 열고, 그 줄을 노란 띠로 표시하고, 초점을 그 줄에 둔다.

### 2.2 종이

긴 글은 어두운 판보다 종이 위가 읽기 편하다. 어두운 사무실 화면 안에서 “서류를 펼쳤다”는 것도 바로 읽힌다. 그래서 문서 본문만 아이보리 종이(`--paper`)에 검은 글자(`--paper-ink`, 13.8:1)로 놓았다. 종이 오른쪽 위에 검은 꼬리표로 종류를 적는다(“기획서 · 이슈 #28”).

| 종류 | 지면 |
|---|---|
| 기획서 | 이슈 폼 칸이 그대로 소제목(배경과 목표 · 범위 · 하지 않을 것 · 완료 기준). 완료 기준 체크는 ✓ |
| 회의록 | **대화**로 보인다. 협의 기록 표 한 줄 = 말 한 번. 왼쪽에 보낸 쪽 이름표(에이전트 색 바탕)와 “→ 받는 쪽”, 오른쪽에 그 에이전트 색을 옅게 깐 말 칸. 사용자(ROWAN)는 오른쪽에 호박 말 칸. 결정·후속은 아래 붙은 호박 메모지 |
| 결정 | 테두리 상자 하나: 결정 한 문장(크게) + 이유 + 빨간 “✅ 결재 · 결과 · 날짜” |
| 보고서 | 무엇을 했나 · 확인한 것 표(PR 템플릿 그대로) · 전후 그림 둘 |

- 모든 종이 맨 아래에 원문 링크(GitHub ↗)를 단다. `review`가 결재돼 공개된 문서는 원문 링크가 없다(plan 6.3).

### 2.3 SECRET 문서

- **표지**: 마닐라 서류철(`--manila`, 탭 모양 윗변)에 SECRET 이중 테두리 도장(`--secret-stamp`, 굵게 44px)이 찍혀 있다.
- **보이는 정보**: 종류 · 제목(검은 줄) · 날짜 · 참여 에이전트. 본문 자리는 검은 줄 다섯이다.
- **`review`**: 저장소 이름과 파일철 번호가 보인다. “주인이 결재하면 공개돼요”.
- **`private`**: 폴더 이름(“비공개 프로젝트”), 파일철 번호, 제목까지 지운다. “내용이 서버에 올라오지 않아요. 이런 일이 있었다는 것만 보여요.” 공개 연출이 없다.
- **결재되면**: 도장이 살짝 들렸다가 기울며 아래로 떨어지고(0.9초), 표지 윗부분부터 걷히며 종이가 드러난다. 움직임 줄이기면 도장 없이 0.12초 페이드다.
- **주인이 볼 때**: `review` 본문이 종이로 보이고, 위에 “SECRET · 결재 대기” 띠가 붙는다(결재함으로 가는 링크). `private`는 서버에 본문이 없어 주인도 표지만 본다.
- **화면 읽기**: 표지는 `aria-label="SECRET 문서. 내용은 공개되지 않았습니다"`이다. 검은 줄은 `aria-hidden`이고, 대신 “결재 전이라 가려짐” / “지워짐”을 읽힌다.

### 2.5 진행 상황 (#241)

> 2026-11-10 · 사용자 의견: "서재에서 각 항목이 완료됨 · 진행 중 · 대기 중 이런 것도 표현됐으면 좋겠네. 진행 상황이라던가."

**상태** (단계 판정은 화이트보드 #100과 같음)
- 상태는 **채움 정도가 다른 원 아이콘 + 글자**로 나눈다. 색은 거의 한 가지(아이보리 계열)다.
- 주제 뱃지(#236)가 색을 쓰므로, 상태까지 색을 쓰면 줄이 시끄러워진다. 그래서 상태는 "얼마나 찼나"라는 모양으로만 읽히게 했다.
- 결재 대기만 결재의 호박을 쓴다(1.2 "결재는 호박 하나").

| 상태 | 판정 | 아이콘(12 px) | 글자 · 색 | 대비 |
|---|---|---|---|---|
| 대기 | 열림, 브랜치 · PR 없음 | ○ 빈 원(테두리 1.5 px) | `대기` · 보조색 `#a39d90` | 7.2 |
| 진행 중 | 브랜치 · 커밋 또는 **Draft PR**(기획 결정 2026-11-10: 작업 이슈 선언 대신 브랜치 · Draft PR로 판단) | ◔ 1/4 찬 원 | `진행 중` · 아이보리 `#f3ead8` | 16.2 |
| 검토 | 열린 PR(Draft가 아닌 것) | ◑ 반 찬 원 | `검토` · 아이보리 | 16.2 |
| 완료 | 닫힘 · 병합 | ● 꽉 찬 원 + 안에 ✓(바탕색으로 뚫음) | `완료` · 옅은 초록 회색 `#c9d6c4` | 12.8 |
| + 결재 대기 | 그 파일철에 대기 결재가 있음 | 도장 아이콘(1.2 산출물 확인과 같은) | `결재 대기` · 호박 `#ffb347` | 10.9 |

- 상태 칩 모양은 뱃지(3.6)와 달리 **테두리 · 바탕 없이** 아이콘 + 글자만 둔다. 뱃지와 칩이 같은 상자 모양이면 무엇이 주제고 무엇이 상태인지 헷갈린다.
- 결재 대기는 다른 상태 칩 뒤에 붙는다(`◑ 검토 · ▣ 결재 대기`).
- 완료된 파일철 줄은 제목을 보조색으로 한 단계 흐리게 한다(지운 줄은 아님).
- **모든 파일철은 상태 하나를 가진다**(#301 판정). 판정할 자료가 없으면 열림 → 대기, 닫힘 → 완료다. 상태 칩이 빈 줄은 두지 않는다(거르기 칩 개수의 합 = 전체).
- 제목은 낱말 가운데서 끊지 않는다: `word-break: keep-all`, 아주 긴 낱말만 `overflow-wrap: anywhere`(목록 · 표지 · 문서 머리).

**진척도** (이슈 본문 완료 기준 `- [ ]` / `- [x]` 세기, 없으면 표시 안 함)
- 막대: 폭 48 px · 높이 4 px, 바탕 `--color-line`, 채움 아이보리 `#f3ead8`(완료 상태면 `#c9d6c4`). 끝은 각지게 한다(픽셀 결).
- 옆 숫자: `3/5`, 픽셀 글꼴 11 px, 보조색, 고정폭 숫자
- 다 차면(5/5) 숫자 앞에 ✓를 붙인다. 상태가 완료가 아니어도 그렇다(기준은 다 했고 아직 안 닫힘).
- 화면 읽기: `완료 기준 5개 중 3개`

**자리** (#222 여백 · #236 뱃지와 함께)

| 어디 | 배치 |
|---|---|
| **목록 줄** | 1줄: [새 점] 제목 ……… 날짜(오른쪽). 2줄: **상태 칩** · 주제 뱃지(최대 2) · 에이전트 ……… **진척도 막대 + 숫자**(오른쪽, `flex: none`). 380 px 이하: 2줄에서 주제 뱃지는 하나 + `+1`, 진척도는 숫자만(막대 뺌) |
| **파일철 표지** | 제목 아래 한 줄: 상태 칩 · 주제 뱃지 둘. 그 아래 진척도 막대를 **전폭**(패널 − 32 px, 높이 6 px) + `완료 기준 3/5` |
| **문서 머리** | 표지(제목 · 칩 줄 · 진척도 막대)가 함께 보이는 화면에서는 **경로 줄에 상태 · 진척도를 두지 않는다**(제목 아래에 이미 있음, #301 판정). 주제 뱃지도 경로 줄에 두지 않고 3.6대로 제목 아래 한 줄 |

**거르기 · 정렬** (서재 파일철 목록 위, 한 줄)
- 거르기 칩 다섯: `전체` · `진행 중` · `검토` · `대기` · `완료`(각 개수). 하나만 고르는 칩 묶음(`role="radiogroup"`)이고, 처음은 `전체`다. 결재 대기는 따로 토글 칩 `결재 대기만`이다.
- 정렬 기본은 **진행 중 → 검토 → 결재 대기가 걸린 것 → 대기 → 완료**, 같은 상태 안에서는 최근 갱신순이다. 오른쪽 끝 `정렬 ▾`에서 `최근 갱신` · `번호`로 바꿀 수 있다.
- 고른 거르기 · 정렬은 브라우저에 기억한다(서재를 다시 열면 그대로).
- 380 px 이하에서는 거르기 칩이 가로 스크롤 한 줄이다(줄바꿈 안 함).

**방문자 · SECRET**
- 상태와 진척도는 방문자에게도 보인다(일의 진행은 공개해도 되는 정보).
- 비공개 저장소 파일철은 상태 칩만 보이고, 진척도 · 주제 뱃지는 숨긴다(#182 · #236 규칙). 제목은 지금처럼 SECRET이다.

### 2.6 완료 파일철을 배포별로 묶기 (#462)

> 2026-11-14 · 사용자 요청: "완료된 이슈를 배포 단위로 묶어서 아코디언으로 잡혀 있게 할 수 있나?" 한 프로젝트 폴더 안의 파일철 목록에만 쓴다. 줄 하나의 모양(2.5 · 3.6)은 그대로다.

```
┌ 거르기 칩 ─ [전체] 진행 중 2 · 검토 1 · 대기 3 · 완료 41   정렬 ▾ ┐
│ 지금 하는 일 6                                            (늘 펼침) │
│   ◔ #461 메모 · 휴 손 몰림 …                                       │
│   …                                                               │
│ ▾ 다음 배포 대기 · 완료 4                                           │
│   ● #460 쪽지 1단계 …                                              │
│ ▾ 11.14 배포 핫픽스 · #442 · 3건                                    │
│   둘러보기 끊김 · 검토 칸                                            │
│   ● #456 …                                                        │
│ ▸ 11.12 배포 · #434 · 11건                                          │
│   둘러보기 자동 시작 없앰 · 타임랩스 하루 흐름 · 표정                 │
│ ▸ 11.11 배포 2차 · #426 · 9건                                       │
└───────────────────────────────────────────────────────────────────┘
```

**묶음 순서 (위에서 아래)**
1. **지금 하는 일**: 진행 중 · 검토 · 대기 · 결재 대기(완료가 아닌 모든 것)를 맨 위 한 묶음으로 둔다. 접지 않고, 머리 줄도 접기 단추가 아닌 소제목이다. 안의 정렬은 2.5 기본 정렬 그대로다.
2. **다음 배포 대기**: 마지막 배포 뒤에 완료된 파일철이다(dev에는 들어갔지만 아직 main에 없음). 아코디언이고 처음에는 펼친다. 비어 있으면 묶음을 두지 않는다.
3. **배포 묶음**: 최근 배포가 위에 온다. **가장 최근 배포 하나만 처음에 펼친다.** 나머지는 접는다.
4. 배포 PR이 하나도 없는 저장소(비공개 · 배포 없는 프로젝트)는 **완료 날짜의 달**로 묶는다(`2026년 11월 · 완료 23건`). 모양과 규칙은 같다.

**머리 줄 (접는 단추)**
- 1줄: `▸`/`▾`(12 px 픽셀 삼각형, 90° 돎) · **`11.14 배포`**(KST 병합 날짜, 갈무리 Bold 13, 아이보리) · `#442`(보조색, 누르면 GitHub 배포 PR ↗, 따로 초점이 가는 링크) ……… 오른쪽에 `12건`.
- 2줄(접혀도 보임): 배포 PR 제목에서 `—` 뒤 요약을 한 줄로 보이고, 넘치면 `…`로 자른다. 보조색 `#a39d90`이고 12 px다. 요약이 없으면 2줄은 없다.
  - 예: `deploy: dev → main (2026-11-10 3차) — 방 확장 · 라운지 동작 · …` → `방 확장 · 라운지 동작 · …`
- 날짜는 **KST 병합 날짜**다(제목 괄호 속 날짜와 같음: #434는 11-11 15:32 UTC 병합 = 11.12). 제목 괄호에 날짜 뒤 말(`2차` · `핫픽스`)이 있으면 그대로 붙인다(`11.11 배포 2차`, `11.14 배포 핫픽스`).
- 머리 줄 높이는 접힘 52 px(두 줄)이다. 위쪽 경계선 1 px `--color-line`, 바탕은 목록과 같다. 호버 시 바탕을 `--surface-raised`로 바꾼다.
- **새 점**(1.6): 묶음 안에 새 파일철이 있으면 접힌 머리 줄의 날짜 앞에 6 px 아이보리 점을 둔다.
- **결재 대기**는 완료 묶음에 없다(결재 대기는 '지금 하는 일'에 있음).

**펼치기 · 접기**
- 머리 줄 아무 데나 누르면 바뀐다. 단, 배포 PR 링크는 링크로 동작한다.
- 180 ms `--ease-out`으로 높이가 열리고, 삼각형이 같이 돈다. 움직임 줄이기면 바로 바뀐다.
- 여러 개를 함께 펼 수 있다(하나 펴면 다른 것이 닫히는 방식이 아님).
- 사용자가 펴고 접은 상태는 브라우저에 기억한다(2.5 거르기와 같은 저장). 새 배포가 생기면 그 배포만 펼침으로 시작한다.

**거르기 · 정렬 · 검색과의 관계**
- **`전체`**: 위 순서 그대로다.
- **`완료`**: '지금 하는 일'을 빼고, 다음 배포 대기 + 배포 묶음만 보인다. 펼침 상태는 그대로다.
- **`진행 중` · `검토` · `대기` · `결재 대기만`**: 완료 파일철이 없으므로 아코디언 없이 지금처럼 평평한 목록이다.
- **정렬** `번호` · `최근 갱신`: 묶음 순서(배포 최신순)는 그대로 두고, **묶음 안에서만** 정렬한다. 묶음 안 기본 정렬은 완료 시각 최신순이다.
- **검색**(지금은 없음, 생기면): 맞는 파일철이 있는 묶음만 보이고, 그 묶음은 **잠시 펼친다**(기억한 상태는 바꾸지 않음). 머리 줄 개수는 `3 / 12건`(맞는 수 / 전체)이다. 검색을 지우면 기억한 펼침으로 돌아간다.
- 새 점 · 회의 재연에서 들어오기(2.1)로 어떤 파일철을 열면, 그 파일철이 든 묶음을 펼친다.

**어느 배포에 묶나** (코더 몫, 디자인 쪽 기준)
- 파일철은 **완료(닫힘 · 병합)된 뒤 처음 병합된 배포 PR**(base `main`, 제목 `deploy:`)에 묶인다. 배포 PR이 포함한 PR의 `Closes` · `Refs`로 알 수 있으면 그것을 먼저 쓴다.
- 배포 뒤에 다시 열렸다 닫힌 파일철은 마지막으로 닫힌 뒤의 배포에 묶는다(한 파일철은 한 묶음에만 있음).

**키보드 · 화면 읽기**
- 머리 줄은 `<button aria-expanded aria-controls>`이고, 묶음 내용은 `role="region"` + `aria-labelledby`(머리 줄)다. 제목 구조를 위해 버튼을 `<h3>`로 감싼다.
- 화면 읽기 이름: `11월 14일 배포 핫픽스, PR 442, 완료 3건, 방 확장 · 라운지 동작 …` + 펼침 상태다. 삼각형은 장식(`aria-hidden`)이다.
- Tab: 머리 줄 → (펼쳤으면) 그 안 파일철 줄들 → 다음 머리 줄. 배포 PR 링크는 머리 줄 다음 Tab 자리다.
- Enter · Space로 펴고 접는다. 접힌 묶음 안 줄은 Tab에 걸리지 않는다(`hidden`).
- '지금 하는 일'은 버튼이 아닌 `<h3>` 소제목이다.

**휴대폰 (시트, ≤ 640 px)**
- 머리 줄은 44 px 이상 누르기 영역이다. 2줄 요약은 380 px 이하에서도 한 줄로 두고 `…`로 자른다.
- 날짜는 `11.14`, 개수는 `12건`으로 줄이지 않는다. PR 번호는 380 px 이하에서 숨기고, 펼친 묶음 맨 위 `배포 PR #442 ↗` 한 줄로 옮긴다.
- 펼칠 때 그 머리 줄이 시트 위쪽에 오도록 스크롤한다(펼친 내용이 아래로 밀려 안 보이는 일 막기).

**방문자 · SECRET**
- 배포 묶음은 방문자에게도 보인다. 비공개 파일철은 묶음 안에서 지금처럼 SECRET 줄이고, 개수에는 센다.
- 배포 PR 요약은 공개 저장소의 PR 제목이라 그대로 보인다.

**판정**: 데스크톱 패널 480 px · 휴대폰 390 px에서 기본 상태, 펼친 둘, `완료` 거르기, 키보드만으로 펼치고 접기를 본다.

## 3. 화이트보드 칸반

### 3.1 캔버스

- `surface_whiteboard`(1.5 × 1.0 m)에 붙이는 캔버스는 **1536 × 1024**(1024 px/m)다.
- 모델의 보드는 흰색(#f4f4f0)으로 구워져 있다. 그래서 캔버스는 **투명 바탕**에 카드·메모지·마커 글씨만 그린다. 구운 보드 음영이 비쳐 “보드에 붙인 카드”로 보인다.
- 시안은 흰 바탕 위에 깔아 보여 준다.

| 구역 | 내용 |
|---|---|
| 칸 셋 | 진행 중 · 검토 · 완료. 마커 글씨 제목(48px 굵게) + 오른쪽에 장 수(24px) + 마커 밑줄, 칸 사이 세로 마커 줄 |

### 3.5 눌러서 보기 (#234)

> 2026-11-10 · 사용자 의견: "화이트보드를 클릭하면 해당 위치를 확대해서 볼 수 있게 하거나, 실제 그래픽과 동일하게 또는 더 자세하게 영역을 둘러볼 수 있게."

**들어가기**
- 보드 면(`surface_whiteboard`)에 호버하면 테두리 1 px 청록 + 커서 pointer + 꼬리표 `화이트보드 · 크게 보기`(다른 3D 사물 호버와 같음)다.
- 누르기 · 탭 · Enter(보드가 탭 순서에 들어감, `aria-label="화이트보드 크게 보기"`)로 들어간다.
- 둘러보기(#207) 보드 컷에서는 바에 `[보드 크게 보기]` 버튼이 하나 더 생긴다(선택 기능).

**비행 · 구도** (데스크톱)
- 카메라가 보드 정면(보드 면 법선 방향)에서, **보드 가로가 왼쪽 영역 폭의 88%**가 되는 거리로 날아간다. 화각 32°는 그대로이고, 높이는 보드 가운데(1.50 m)다.
- **눌린 칸 쪽으로 10% 치우쳐** 멈춘다. Enter로 들어가면 가운데다.
- 비행은 1.2초, ease-in-out, 둘러보기와 같은 곡선(#207 10.3)이다. 충돌 규칙(#208)은 비행 중 끈다. 움직임 줄이기면 0.3초 페이드 컷이다.
- 도착하면 3D 장면 나머지를 40%로 어둡게 한다(보드만 밝게, 0.3초).

**보드 화면** (도착 뒤 0.2초 페이드)
- 3D 보드 위에 **같은 배치의 HTML 캔버스**를 덧그린다. 보드 레이아웃 함수(지금 텍스처를 그리는 것)를 그대로 쓰고, 기기 픽셀 비율(DPR)로 그려 선명하게 한다. 위치 · 크기는 3D 보드 면을 화면에 투영한 사각형에 정확히 맞춘다. 그래서 들어가는 순간 "3D가 선명해지는" 것으로 보이고, 다른 그림이 뜨지 않는다.
- **둘러보기**: 끌기 = 옮기기, 휠 · 핀치 = 확대 1× – 3×(1×가 도착 구도). 보드 바깥이 보이지 않게 가장자리에서 멈춘다(탄성 없이 멈춤). 칸 머리(진행 중 · 검토 · 완료)를 누르면 그 칸이 화면 가운데 · 2×로 0.4초에 간다. 카메라는 움직이지 않는다(덧그림만 확대 · 이동, 3D 보드는 덧그림 아래에 가려짐).
- 3× 확대에서 카드 글씨 24 px 줄이 실제 크기로 읽힌다(#번호 · 이름 · 두 줄 제목).
- "+N"(넘친 카드)을 누르면 그 칸의 숨은 카드가 아래로 펼쳐진다(덧그림에서만, 3D는 그대로).
- **나가기**: Esc · `← 사무실로` 버튼(왼쪽 위, 기존 `← 책상으로` 자리 옆) · 보드 바깥 빈 곳 누르기. 덧그림이 0.2초에 사라지고, 카메라가 들어오기 전 시점으로 1.2초에 돌아간다. 초점은 보드로 돌아온다.

**카드 요약 = 카드 위 팝오버** (옆 패널이 아님)
- 옆 패널(#170)은 서재 · 결재함 문서용이고, 열면 3D가 왼쪽으로 줄어들어(맞추기) 보드 구도가 깨진다. 그래서 카드는 **카드 옆 팝오버**로 보인다.
- 팝오버: 폭 300 px, `--color-surface` 판 + 1 px 선 + 카드 쪽 꼬리(10 px). 카드 오른쪽에 두고, 화면 밖이면 왼쪽에 둔다.
  1. 머리: 에이전트 색 점 + 이름 · `#번호`(이 저장소) 또는 `저장소#번호`(#182 규칙)
  2. 제목(15 px, 줄바꿈)
  3. 단계 칩(`진행 중` · `검토` · `완료`) + PR이면 `PR #n · 열림/병합됨`
  4. 맡은 에이전트(여럿이면 점 여럿) · `마지막 갱신 11-10 14:32`
  5. 링크: `GitHub에서 보기 ↗`(새 탭) · 서재에 그 문서가 있으면 `서재에서 열기`(옆 패널로 열고 보드에서 나감)
- 다른 카드를 누르면 팝오버가 그 카드로 옮겨 간다. Esc는 팝오버 → 보드 순서로 닫는다.
- **공개 규칙**(#182)
  - 방문자: 공개 저장소 카드만 위 내용이다.
  - 비공개 카드: 덧그림에서도 제목 대신 `책상 방 작업(비공개)` + 자물쇠로 보이고, 팝오버는 머리 · `비공개` 칩 · 마지막 갱신만 있다. 링크는 없다.
  - 주인: 모두 보인다.

**휴대폰 (≤ 640 px)**
- 보드를 탭하면 비행 없이 **전체 화면 2D 보드**가 아래에서 올라온다(0.24초, 옆 패널 시트와 같은 결).
- 머리: `화이트보드` + ✕. 그 아래 **칸 탭 셋**(진행 중 n · 검토 n · 완료 n)이 있고, 탭이나 좌우 스와이프로 칸을 바꾼다.
- 칸 안은 카드 세로 목록(한 줄에 한 장, 3D와 같은 종이 · 색 띠 · 글자)이다. 맨 아래에 노란 결정 메모지 셋을 둔다(완료 탭에서만).
- 카드 탭 → 아래 시트(높이 55%)에 위 팝오버와 같은 내용
- 뒤로 · ✕ · 아래로 끌기로 닫는다.

**키보드 · 화면 읽기**
- 보드 화면은 `role="grid"`(칸 = 열, 카드 = 칸 안 줄)다. ← → 로 칸, ↑ ↓ 로 카드, Enter로 팝오버, Esc로 닫기(팝오버 → 보드)다. `+` · `-`로 확대 · 축소하고, 화살표를 Shift와 함께 누르면 옮기기다.
- 카드 이름 예: "진행 중, 루프, #207 둘러보기, 2번째 중 1"
- 초점 고리: 청록 2 px, 카드 바깥 3 px
- 대비: 덧그림은 3.3절 값 그대로다. 팝오버는 패널 글자(16.2 : 1 · 7.2 : 1)와 같다.

**판정**: 데스크톱은 "누르기 → 비행 → 덧그림 → 끌기 · 휠 → 카드 팝오버 → Esc 복귀" 연속 컷을 봅니다. 3× 확대에서 카드 글씨가 읽히는지 근접으로 보고, 휴대폰 2D 보드와 키보드만으로 열고 닫기도 확인합니다.

### 3.6 주제 뱃지 (#236)

**주제 표** (색만으로 구별하지 않는다: 늘 아이콘 + 글자)

- 말머리에 둘이 붙은 것(`[디자인·3D·기능]`)은 앞에서부터 두 개(디자인 · 3D)를 쓴다. 라벨과 말머리가 둘 다 있으면 라벨이 먼저고, 모자란 칸을 말머리로 채운다.

  - 셋째 주제(`기능`)는 뱃지가 최대 2개라 빠진다. 화면 읽기는 `주제: …`가 알려 준다.

## 4. 옆 패널: 서재 · 결재함 (#170)

> 2026-11-08 · 사용자 요청: "서재 · 결재함이 열릴 때 별도 창이 아니라 화면 오른쪽 사이드에 열리게, 오피스 렌더링은 왼쪽 영역 가운데로." 1 · 2절의 "3D 위에 뜬 패널"을 이 절이 대신한다. 내용(목록 · 한 건 · 도장 · 종이 · 회의록 대화 · SECRET)은 그대로 둔다.

```
데스크톱 (≥ 1025px)
┌──────────────────────────────────────┬─────────────────────┐
│ ← 책상으로        (에이전트 목록)       ┃ [서재] [결재함 3]  ✕ │
│                                      ┃─────────────────────│
│        3D 사무실: 왼쪽 영역 가운데      ┃  패널 내용           │
│                                      ┃  (스크롤)            │
│                    [타임랩스]          ┃                     │
│            (WASD 안내 · 자막)          ┃                     │
└──────────────────────────────────────┴─────────────────────┘
                                       ↑ 끌어서 너비 바꾸기
```

**패널**
- 화면 오른쪽 끝에 붙어 위에서 아래까지 채운다(바깥 여백 · 그림자 없음). 왼쪽 경계선 1px `--color-line`, 바탕 `--color-surface`(불투명)이다.
- 너비: 처음 480px. 최소 380px, 최대 min(760px, 화면의 55%). 641–1024px 화면에서는 처음 min(420px, 50%)이다.
- **끌어서 너비 바꾸기**: 왼쪽 경계에 8px 잡는 띠를 둔다. 평소 1px 선, 호버 · 끄는 중이면 2px 청록. 키보드는 띠에 초점을 두고 ← → 로 16px씩 바꾼다. 바꾼 너비는 `localStorage`에 기억하고 두 탭이 같이 쓴다.
- **서재 · 결재함 = 한 패널의 두 탭**: 머리에 `[서재] [결재함 N]`, 오른쪽 끝 ✕. 탭을 바꾸면 내용만 바뀌고(120 ms 페이드) 너비 · 위치는 그대로다. 다른 쪽 3D 사물(책장 · 서류함)을 누르면 그 탭으로 바뀐다.
- **열기 · 닫기**: 240 ms `--ease-out`으로 오른쪽에서 밀려 들어온다(닫기는 거꾸로). 움직임 줄이기면 바로 바뀐다.
- 패널 머리 높이 48px, 탭은 갈무리 12px, 고른 탭은 아이보리 밑줄 2px. Esc는 패널 안 한 단계(한 건 → 목록) → 패널 닫기 순서다.

**3D 중심 옮기기 · 맞추기**
- 캔버스는 화면 전체 그대로 두고, 카메라 `setViewOffset`으로 그림 중심을 왼쪽으로 패널 너비의 절반만큼 옮긴다. 캔버스 크기를 바꾸지 않아 다시 그리기 비용이 없다(책상 방 정보 패널과 같은 방식).
- **맞추기**(2026-11-08 더함, #175 리뷰): 중심만 옮기면 방(1280에서 약 1150px 폭)이 왼쪽 영역에 다 들어오지 않는다. 그러면 출입문과 책장 · 결재 서류함이 패널 밑에 숨어, 사물을 눌러 탭을 바꿀 수 없다. 그래서 그림을 함께 줄인다.
  - 배율 = min(1, (왼쪽 영역 폭 − 48) ÷ 닫혔을 때 방의 화면 폭). 1280 / 480 기준 약 0.65다.
  - 방의 화면 폭은 지금 카메라에서 방 바닥 · 벽 경계 상자를 투영해 잰다. 사용자가 돌리거나 확대한 상태면 그 상태에 배율을 곱하고, 닫으면 되돌린다.
  - 세로는 왼쪽 영역 가운데 그대로다. 휴대폰 시트에서는 맞추지 않는다(너무 작아짐).
- 옮기기 · 맞추기 모두 패널과 같은 240 ms · 같은 곡선이다. 끄는 동안에는 바로 따라가고, 움직임 줄이기면 바로 바뀐다.
- 패널이 3D 오른쪽을 덮지만 바탕이 불투명이라 비치지 않는다. 사물 클릭 · WASD는 왼쪽 영역에서만 받는다.

**패널이 열렸을 때 다른 것들**
- "← 책상으로" · 에이전트 목록(왼쪽 위): 그대로.
- HUD 도크(#167): 패널 왼쪽으로 옮긴다(`right` = 패널 너비 + 16px). 서재 · 결재함 버튼은 도크에서 숨기고(탭이 대신함), 타임랩스만 남는다.
- 아래 가운데 안내(WASD) · 회의 자막: 왼쪽 영역의 가운데로 옮긴다.
- 말풍선 · 꼬리표: 왼쪽 영역 밖(패널 아래)으로 나가면 왼쪽 영역 안으로 밀어 넣는다.
- 타임랩스: 재생을 시작하면 패널을 닫는다. 막대에 화면 폭 전체가 필요하기 때문이다. 문서 뷰어의 "이 일의 이력 재생"도 패널을 닫고 재생한다. 재생 중에는 서재 · 결재함을 열지 않는다(도크에서 숨겨져 있음).

**휴대폰 (≤ 640px): 아래에서 올라오는 시트**
- 높이 두 단계: 반(55% 높이)과 전체(92%). 처음에는 반으로 열린다. 위쪽 손잡이(36 × 4px)를 끌어 오르내리고, 반에서 아래로 끌면 닫힌다.
- 반 단계에서는 3D가 위쪽 45% 영역의 가운데로 옮겨 간다(세로 view offset). 사무실을 보면서 목록을 고를 수 있다.
- 종이(문서 읽기)와 결재 한 건은 전체 단계로 자동으로 올라간다.
- 탭 · ✕는 시트 머리에, 도크는 시트가 열린 동안 숨긴다.
- 시간은 데스크톱과 같다(240 ms, 움직임 줄이기면 바로).
