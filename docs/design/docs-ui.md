## 1. 결재함

### 1.1 구조 (코더와 합의, #25)

| 화면 | 내용 |
|---|---|
| 목록 | 탭 “대기 N / 처리됨”. 카드 = 종류 배지 · 날짜 / 이슈 제목 / 요청 에이전트(이름 · 역할, 에이전트 색) · 파일철(저장소 #이슈). 오래된 것부터. 처리됨 카드엔 `✅ 결과` |
| 한 건 | ← 목록 / 종류 배지 / 제목 / 요청 에이전트 · 파일철(GitHub 원문 ↗) · 날짜 / 내용 / 선택지 / 추천 이유(접힘) / 의견 / [나중에] [결재] |
| 결재 직후 | 고른 선택지 위에 결재 도장 → “#이슈에 ✅ 결재 댓글을 남겼어요” → 1.2초 뒤 다음 건(없으면 목록) |
| 방문자 | “결재 대기 N건” + SECRET 표지 목록(종류 · 요청 에이전트 · 날짜만). 내용 · 선택지 · 이슈 제목 없음 |
| 로그인 입구 | 출입문 화면 오른쪽 아래 구석 열쇠 점(평소 25% 밝기, 호버·초점이면 청록) + `?owner`. 로그인되면 HUD에 `OWNER` 꼬리표 |

- 패널: 3D 사무실 위 오른쪽, 폭 440px(`--approval-panel-w`). 640px 이하에서는 전체 화면이다.
- 클래스는 #25의 `.approval-box`, `.approval-count`, `.approval-signin`, `.approval-list`, `.approval-item`, `.approval-reason`, `.approval-actions`를 그대로 쓰고, 탭·한 건 화면용 이름을 더했다(`.approval-tabs`, `.approval-detail`, `.approval-options`, `.approval-option`, `.approval-badge`, `.approval-stamp`, `.approval-note`).

**종류별 선택지** (서버도 같은 값을 받음, #25)

| 종류 | 선택지 | 의견 필수 |
|---|---|---|
| 결정 요청 | 요청의 선택지 N개 + “반려” | 반려 |
| 산출물 확인 | 승인 / 반려 | 반려 |
| 문서 공개 | 공개 / 고쳐서 공개 / 계속 SECRET | 고쳐서 공개 · 계속 SECRET |

의견이 필수인 선택지를 고르면 의견 라벨 뒤에 빨간 `*` 안내가 붙고, 비어 있으면 결재 버튼이 꺼진다. 서버(`needsOpinion`, #25)도 같은 규칙으로 400을 돌려준다. “고쳐서 공개”는 무엇을 고칠지 에이전트가 알아야 해서 필수다(2026-11-08, #64에서 서버 규칙에 맞춤).

| 고른 것 | 의견 라벨 안내 |
|---|---|
| 반려 | `* 반려에는 이유가 필요해요` |
| 고쳐서 공개 | `* 무엇을 고칠지 적어 주세요` |
| 계속 SECRET | `* 공개하지 않는 이유를 적어 주세요` |
| 그 밖 | `(선택)` |

“고쳐서 공개”는 반려가 아니라서 선택지 글자를 흐리게 하지 않는다(흐린 글자는 반려 · 계속 SECRET만).

### 1.2 시각 결정

- **결재는 호박 하나.** 탭, 주 버튼, 선택 표시, 배지가 모두 `--approval-accent`(호박)이다. 메모의 결재 도장(#32), 책상 방 단말기(주인의 색)와 이어진다.
- **종류는 모양으로 구분한다.** 처음에는 종류마다 색을 주려 했다. 그런데 청록·호박·라벤더가 에이전트 색(루프·메모·메시)과 같아서, 카드 하나에 “요청 에이전트 색 띠”와 “종류 색”이 겹쳤다. 그래서 색은 에이전트에만 쓰고, 종류는 아이콘 + 글자 + 배지 모양으로 나눴다.
  - 결정 요청: 갈림길 아이콘, 테두리만 있는 배지
  - 문서 공개: 문서 아이콘, 채운 배지
  - 산출물 확인: 도장 아이콘, 사선 무늬 배지. 무늬는 호박 16%, 3px 줄 + 4px 틈(주기 7px). 처음 안의 28%는 12px 픽셀 글자 획과 섞여 읽기 어려웠다(#64 앱 확인). 가장 진한 줄 위에서도 글자 대비 7.0 : 1
- 패널은 `color-scheme: dark`, `scrollbar-color: var(--bubble-dim-line) transparent`, `scrollbar-width: thin`이다. 기본 스크롤바와 textarea 손잡이가 밝게 떠 보이지 않게 한다(#64 앱 확인).
- **긴 글은 본문 글꼴로.** 라벨·배지·날짜는 갈무리(12px)를 쓴다. 제목·내용·선택지는 읽을 문장이라 `--font-text`(14~17px)로 썼다. #18 말풍선은 짧은 대사라 픽셀 폰트였지만, 결재 내용은 몇 문장이다.
- **내용은 제한된 마크다운이다**(문단 · 목록 · 굵게 · 인라인 코드 · 링크 · 표). 표는 패널 안에서 가로 스크롤한다(`tabindex=0`, `role=region`으로 키보드 스크롤 가능).
- **도장은 고른 선택지 위에.** 처음에는 제목 옆에 찍었더니 제목과 날짜를 가렸다. 고른 선택지 카드 오른쪽에 찍으니 “무엇을 결재했는지”가 도장으로 남는다.
  - 도장: 지름 88px, −12° 기울임, `--stamp-red`
  - 판 위 대비 6.3:1. 장식이기도 하지만 글자이기도 해서 대비를 맞췄다.

### 1.3 움직임

| 동작 | 기본 | 움직임 줄이기 |
|---|---|---|
| 도장 | 1.9배 크기에서 0.4초 만에 쾅(살짝 튕김), 판이 2px 눌림 | 찍힌 채로 바로 나타남(`--approval-stamp-ms: 0`) |
| 다음 건 | 도장 뒤 1.2초(`--approval-next-ms`) | 같음(읽을 시간) |

### 1.4 접근성

- **키보드만으로 결재까지 간다.** Tab → 목록 카드(버튼) → Enter → 제목에 초점 → 선택지(라디오, 화살표 키) → 의견 → Enter로 결재. Esc는 목록으로 돌아간다.
- 반려·계속 SECRET을 고르면 의견 라벨에 “* 반려에는 이유가 필요해요”가 붙는다. 의견이 비어 있으면 결재 버튼이 꺼진다. 결재를 누르면 `aria-invalid`도 켜진다.
- 결재가 끝나면 `role=status` 영역이 읽어 준다: “결재했어요: 제목 — 결과. 저장소 #이슈에 댓글을 남겼어요.”
- 보내기에 실패하면 `role=alert`로 알린다. 고른 선택지와 의견은 그대로 둔다.
- 초점 링은 청록(#18 규칙: 네온 = 누를 수 있음)이다.

## 2. 서재 문서 뷰어

### 2.1 구조

- **왼쪽 목록**: 프로젝트 폴더(저장소 하나 = 폴더 하나, `private`는 “비공개 프로젝트” 하나로 모음) → 파일철(이슈 하나). SECRET 파일철은 방문자 목록에서 **제목도 가린다**(#25 방문자 뷰처럼 종류·날짜·참여 에이전트만).
- **오른쪽**: 파일철 머리(저장소 · 파일철 #번호 · 상태 / 제목 / 참여 에이전트) → 목차 탭(1. 기획서 → 2. 회의록 → 3. 결정 → 4. 보고서, 있는 것만) → 종이 한 장.
- **좁은 화면(≤ 760px)**: 목록이 위로 올라가고(높이 220px 스크롤), 종이가 전체 폭이 된다.
- **회의 재연에서 들어오기**: 말풍선(#18)엔 첫 문장만 나온다. “전문 보기”를 누르면 뷰어가 그 파일철의 회의록을 열고, 그 줄을 노란 띠로 표시하고, 초점을 그 줄에 둔다.

### 2.2 종이

긴 글은 어두운 판보다 종이 위가 읽기 편하다. 어두운 사무실 화면 안에서 “서류를 펼쳤다”는 것도 바로 읽힌다. 그래서 문서 본문만 아이보리 종이(`--paper`)에 검은 글자(`--paper-ink`, 13.8:1)로 놓았다. 종이 오른쪽 위에 검은 꼬리표로 종류를 적는다(“기획서 · 이슈 #28”).

| 종류 | 지면 |
|---|---|
| 기획서 | 이슈 폼 칸이 그대로 소제목(배경과 목표 · 범위 · 하지 않을 것 · 완료 기준). 완료 기준 체크는 ✓ |
| 회의록 | **대화**로 보인다. 협의 기록 표 한 줄 = 말 한 번. 왼쪽에 보낸 쪽 이름표(에이전트 색 바탕)와 “→ 받는 쪽”, 오른쪽에 그 에이전트 색을 옅게 깐 말 칸. 사용자(ROWAN)는 오른쪽에 호박 말 칸. 결정·후속은 아래 붙은 호박 메모지 |
| 결정 | 테두리 상자 하나: 결정 한 문장(크게) + 이유 + 빨간 “✅ 결재 · 결과 · 날짜” |
| 보고서 | 무엇을 했나 · 확인한 것 표(PR 템플릿 그대로) · 전후 그림 둘 |

- 모든 종이 맨 아래에 원문 링크(GitHub ↗)를 단다. `review`가 결재돼 공개된 문서는 원문 링크가 없다(plan 6.3).

### 2.3 SECRET 문서

- **표지**: 마닐라 서류철(`--manila`, 탭 모양 윗변)에 SECRET 이중 테두리 도장(`--secret-stamp`, 굵게 44px)이 찍혀 있다.
- **보이는 정보**: 종류 · 제목(검은 줄) · 날짜 · 참여 에이전트. 본문 자리는 검은 줄 다섯이다.
- **`review`**: 저장소 이름과 파일철 번호가 보인다. “주인이 결재하면 공개돼요”.
- **`private`**: 폴더 이름(“비공개 프로젝트”), 파일철 번호, 제목까지 지운다. “내용이 서버에 올라오지 않아요. 이런 일이 있었다는 것만 보여요.” 공개 연출이 없다.
- **결재되면**: 도장이 살짝 들렸다가 기울며 아래로 떨어지고(0.9초), 표지 윗부분부터 걷히며 종이가 드러난다. 움직임 줄이기면 도장 없이 0.12초 페이드다.
- **주인이 볼 때**: `review` 본문이 종이로 보이고, 위에 “SECRET · 결재 대기” 띠가 붙는다(결재함으로 가는 링크). `private`는 서버에 본문이 없어 주인도 표지만 본다.
- **화면 읽기**: 표지는 `aria-label="SECRET 문서. 내용은 공개되지 않았습니다"`이다. 검은 줄은 `aria-hidden`이고, 대신 “결재 전이라 가려짐” / “지워짐”을 읽힌다.

## 3. 화이트보드 칸반

### 3.1 캔버스

- `surface_whiteboard`(1.5 × 1.0 m)에 붙이는 캔버스는 **1536 × 1024**(1024 px/m)다.
- 모델의 보드는 흰색(#f4f4f0)으로 구워져 있다. 그래서 캔버스는 **투명 바탕**에 카드·메모지·마커 글씨만 그린다. 구운 보드 음영이 비쳐 “보드에 붙인 카드”로 보인다.
- 시안은 흰 바탕 위에 깔아 보여 준다.

| 구역 | 내용 |
|---|---|
| 칸 셋 | 진행 중 · 검토 · 완료. 마커 글씨 제목(48px 굵게) + 오른쪽에 장 수(24px) + 마커 밑줄, 칸 사이 세로 마커 줄 |
| 카드 | 칸당 최근 4장, 넘치면 “+N”. 카드 = 종이(`--board-card`), 위에 에이전트 색 띠(14px), `#번호 · 이름`(24px), 제목 두 줄(48px 굵게, 띄어쓰기 단위로 줄바꿈). 카드마다 ±1° 기울여 손으로 붙인 느낌 |
| 최근 결정 | 오른쪽 노란 메모지(`--board-note`) 셋: 결정 한 줄(48px 굵게) + 보충(24px) + #번호 |

### 3.2 거리별로 읽히는 것 (#18 모니터와 같은 규칙)

| 거리 | 보드 가로 | 읽히는 것 |
|---|---|---|
| 기본 카메라 약 14 m | 약 160px | 칸마다 쌓인 카드 수, 에이전트 색 띠, 노란 결정 메모지 셋. 글자는 안 읽힘 |
| 1/4 약 6 m | 약 384px | 칸 제목과 카드 제목(48px → 12px) |
| 바로 앞 | 1536px | #번호·에이전트 이름·결정 보충 |

### 3.3 대비

| 글자 | 바탕 | 대비 |
|---|---|---|
| 마커 `--board-marker` | 흰 보드 | 12.9 : 1 |
| 카드 글자 `--board-card-ink` | 카드 종이 | 16.2 : 1 |
| 메모지 글자 | 노란 메모지 | 13.4 : 1 |

### 3.4 구현 메모 (코더에게)

- 다시 그리는 때: 이슈 상태가 바뀔 때(#24 Action → `docs` 갱신)만이다. 매 프레임 그리지 않는다.
- 카드가 붙는 장면(회의 재연의 **결정** 줄 → 메모가 보드에 카드를 붙이는 동작, plan 6.4)에서는 새 카드만 그 자리에서 0.3초 페이드로 나타나게 한다.
- 재질: 캔버스 판은 투명(alpha)이고, 보드 면에서 1 mm 앞에 둔다. 빛은 구운 보드와 어울리게 `MeshBasicMaterial`에 0.92배 밝기를 권한다(카드 종이가 발광해 보이지 않게).

## 4. 옆 패널: 서재 · 결재함 (#170)

> 2026-11-08 · 사용자 요청: "서재 · 결재함이 열릴 때 별도 창이 아니라 화면 오른쪽 사이드에 열리게, 오피스 렌더링은 왼쪽 영역 가운데로." 1 · 2절의 "3D 위에 뜬 패널"을 이 절이 대신한다. 내용(목록 · 한 건 · 도장 · 종이 · 회의록 대화 · SECRET)은 그대로 둔다.

```
데스크톱 (≥ 1025px)
┌──────────────────────────────────────┬─────────────────────┐
│ ← 책상으로        (에이전트 목록)       ┃ [서재] [결재함 3]  ✕ │
│                                      ┃─────────────────────│
│        3D 사무실: 왼쪽 영역 가운데      ┃  패널 내용           │
│                                      ┃  (스크롤)            │
│                    [타임랩스]          ┃                     │
│            (WASD 안내 · 자막)          ┃                     │
└──────────────────────────────────────┴─────────────────────┘
                                       ↑ 끌어서 너비 바꾸기
```

**패널**
- 화면 오른쪽 끝에 붙어 위에서 아래까지 채운다(바깥 여백 · 그림자 없음). 왼쪽 경계선 1px `--color-line`, 바탕 `--color-surface`(불투명)이다.
- 너비: 처음 480px. 최소 380px, 최대 min(760px, 화면의 55%). 641–1024px 화면에서는 처음 min(420px, 50%)이다.
- **끌어서 너비 바꾸기**: 왼쪽 경계에 8px 잡는 띠를 둔다. 평소 1px 선, 호버 · 끄는 중이면 2px 청록. 키보드는 띠에 초점을 두고 ← → 로 16px씩 바꾼다. 바꾼 너비는 `localStorage`에 기억하고 두 탭이 같이 쓴다.
- **서재 · 결재함 = 한 패널의 두 탭**: 머리에 `[서재] [결재함 N]`, 오른쪽 끝 ✕. 탭을 바꾸면 내용만 바뀌고(120 ms 페이드) 너비 · 위치는 그대로다. 다른 쪽 3D 사물(책장 · 서류함)을 누르면 그 탭으로 바뀐다.
- **열기 · 닫기**: 240 ms `--ease-out`으로 오른쪽에서 밀려 들어온다(닫기는 거꾸로). 움직임 줄이기면 바로 바뀐다.
- 패널 머리 높이 48px, 탭은 갈무리 12px, 고른 탭은 아이보리 밑줄 2px. Esc는 패널 안 한 단계(한 건 → 목록) → 패널 닫기 순서다.

**3D 중심 옮기기 · 맞추기**
- 캔버스는 화면 전체 그대로 두고, 카메라 `setViewOffset`으로 그림 중심을 왼쪽으로 패널 너비의 절반만큼 옮긴다. 캔버스 크기를 바꾸지 않아 다시 그리기 비용이 없다(책상 방 정보 패널과 같은 방식).
- **맞추기**(2026-11-08 더함, #175 리뷰): 중심만 옮기면 방(1280에서 약 1150px 폭)이 왼쪽 영역에 다 들어오지 않는다. 그러면 출입문과 책장 · 결재 서류함이 패널 밑에 숨어, 사물을 눌러 탭을 바꿀 수 없다. 그래서 그림을 함께 줄인다.
  - 배율 = min(1, (왼쪽 영역 폭 − 48) ÷ 닫혔을 때 방의 화면 폭). 1280 / 480 기준 약 0.65다.
  - 방의 화면 폭은 지금 카메라에서 방 바닥 · 벽 경계 상자를 투영해 잰다. 사용자가 돌리거나 확대한 상태면 그 상태에 배율을 곱하고, 닫으면 되돌린다.
  - 세로는 왼쪽 영역 가운데 그대로다. 휴대폰 시트에서는 맞추지 않는다(너무 작아짐).
- 옮기기 · 맞추기 모두 패널과 같은 240 ms · 같은 곡선이다. 끄는 동안에는 바로 따라가고, 움직임 줄이기면 바로 바뀐다.
- 패널이 3D 오른쪽을 덮지만 바탕이 불투명이라 비치지 않는다. 사물 클릭 · WASD는 왼쪽 영역에서만 받는다.

**패널이 열렸을 때 다른 것들**
- "← 책상으로" · 에이전트 목록(왼쪽 위): 그대로.
- HUD 도크(#167): 패널 왼쪽으로 옮긴다(`right` = 패널 너비 + 16px). 서재 · 결재함 버튼은 도크에서 숨기고(탭이 대신함), 타임랩스만 남는다.
- 아래 가운데 안내(WASD) · 회의 자막: 왼쪽 영역의 가운데로 옮긴다.
- 말풍선 · 꼬리표: 왼쪽 영역 밖(패널 아래)으로 나가면 왼쪽 영역 안으로 밀어 넣는다.
- 타임랩스: 재생을 시작하면 패널을 닫는다. 막대에 화면 폭 전체가 필요하기 때문이다. 문서 뷰어의 "이 일의 이력 재생"도 패널을 닫고 재생한다. 재생 중에는 서재 · 결재함을 열지 않는다(도크에서 숨겨져 있음).

**휴대폰 (≤ 640px): 아래에서 올라오는 시트**
- 높이 두 단계: 반(55% 높이)과 전체(92%). 처음에는 반으로 열린다. 위쪽 손잡이(36 × 4px)를 끌어 오르내리고, 반에서 아래로 끌면 닫힌다.
- 반 단계에서는 3D가 위쪽 45% 영역의 가운데로 옮겨 간다(세로 view offset). 사무실을 보면서 목록을 고를 수 있다.
- 종이(문서 읽기)와 결재 한 건은 전체 단계로 자동으로 올라간다.
- 탭 · ✕는 시트 머리에, 도크는 시트가 열린 동안 숨긴다.
- 시간은 데스크톱과 같다(240 ms, 움직임 줄이기면 바로).
