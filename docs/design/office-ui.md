## 1. 한 줄 요약

책상 방 HUD 콜아웃과 **같은 가족**이다(깎은 모서리, 얇은 테두리, 갈무리 픽셀 폰트, 에이전트 색 = 기분 색 자리). 여기에 사무실다운 변형 세 가지를 더했다.

1. 이름표를 판 위로 튀어나온 **서류철 탭**으로 뺐다.
2. 글자는 차가운 흰색 대신 **따뜻한 아이보리**다. 사무실 조명이 호박색이라서다.
3. 출입문 화면은 **책상 방 단말기 옷**(호박색 형광, 이중선 프레임, 반전 제목 표시줄)을 입혔다. 문 너머가 어디인지 색으로 말한다.

## 3. 말풍선 (HTML 오버레이)

### 3.1 종류: 한 가족, 두 크기

| 종류 | 언제 | 모양 |
|---|---|---|
| 대화 · 회의 | 에이전트 ↔ 에이전트 대면 대화(plan 4.1), 회의 재연 | 탭(`MEMO · 대화`) + 판 + 지시선. 타자 효과 |
| 반응 | 방문자가 간식·응원을 줬을 때(plan 7) | 같은 틀, 탭에 하트. 타자 없이 튀어나옴(`--ease-pop`) |
| 비공개 대화 | `private` 등급 에이전트끼리 대화 | 같은 틀, 사선 무늬 + 자물쇠 + 회색 글자 “비공개 대화”. 내용 없음 |
| 상태 꼬리표 | 작업 중 활동(“파일 편집 중”) | 탭·지시선 없는 작은 칩(높이 20px) + 머리를 가리키는 꼭지. 비공개면 “비공개 작업 중” |

- **나눈 이유**: 꼬리표는 작업 내내 떠 있다. 말풍선만큼 크면 네 명이 일할 때 사무실이 글자로 덮인다. 대신 색 띠·글꼴·바탕을 같게 해서 한 가족으로 읽히게 했다.
- **한 에이전트에 하나**: 말풍선이 뜨면 그 에이전트의 꼬리표는 숨는다. 같은 사람이 다시 말하면 자기 말풍선의 문장만 바뀐다.
- 비공개를 말풍선과 꼬리표에서 다르게 쓴 이유: 대화 중인 말풍선에 “작업 중”이라고 쓰면 어색하다. 그래서 말풍선은 “비공개 대화”, 꼬리표와 모니터는 “비공개 작업 중”으로 했다.

### 3.2 생김새 규칙

- **지시선이 닿는 쪽 = 색 띠 + 탭.** 왼쪽 3px 에이전트 색 띠가 지시선에서 이어지고, 반대쪽 아래 모서리를 10px 깎는다. 판이 왼쪽으로 펼쳐지면 모두 거울처럼 뒤집는다(글자는 그대로 왼쪽 정렬).
- 판 바탕은 `--color-surface-alpha`(94%)다. 그래서 밝은 3D 배경 위에서도 글자 대비가 14:1 아래로 떨어지지 않는다. 바깥에 1px 검은 선(`--color-halo`)과 그림자를 둬서 밝은 벽·네온 띠와 판을 떼어 놓는다.
- 테두리는 에이전트 색 55%, 탭은 에이전트 색 바탕 + 검은 글자(`--color-ink`).
- 깎은 모서리는 책상 방 것을 물려받았다. 대신 판 안 이름 줄을 탭으로 빼서 본문이 한 줄 더 들어간다.

### 3.3 배치

- **기준점** = 머리 위 가운데. 앱은 매 프레임 `.ob`의 위치만 바꾼다(책상 방 `bubbleAnchor`와 같은 방식, React 다시 그리기 없음). 아래로 펼칠 때는 기준점을 몸 아래(호버 포드)로 옮겨 얼굴을 덮지 않게 한다.
- **마주 보는 대화는 바깥으로.** 판은 상대 반대쪽으로 뻗는다. 넘치면 상대 쪽으로 뒤집지 않고 판을 안쪽으로 민다(지시선은 판 아래 어디든 닿음).
- **혼자일 때**: 오른쪽 기본. 오른쪽으로 넘치면 왼쪽으로 뒤집는다.
- **위로 넘치면 아래로**: 판 위끝이 `--safe-top`(64px, HUD 윗줄)보다 위면 아래로 펼친다.
- **겹치면 위로 쌓기**: 앞뒤로 선 두 사람처럼 판이 겹치면, 나중에 뜬 말풍선을 겹친 만큼 + 8px 올리고 지시선을 늘린다.
- **화면 밖**: 기준점이 화면 밖이면 말풍선을 숨긴다. 화면 읽기 로그에는 그대로 들어간다.
- 시안의 `fit()`이 위 규칙을 실제로 계산한다. 창 폭을 바꿔 보면 다시 계산된다.

### 3.4 길이와 시간

| 항목 | 값 | 이유 |
|---|---|---|
| 폭 | 최대 248px (모바일 200px) | 갈무리 12px 기준 한 줄 약 18자. 눈이 한 번에 훑는 길이 |
| 줄 | 최대 3줄 · 36자, 넘치면 `…` | 대화 대부분이 한두 줄. 원문은 로그(와 서재 회의록)에 |
| 줄바꿈 | `word-break: keep-all` + `overflow-wrap: anywhere` | 한국어는 어절 단위로 끊고, 긴 영문·경로는 아무 데서나 |
| 타자 | 글자당 28ms, 전체 1초 안 | 36자도 1초. 기다리게 하지 않는 선 |
| 머무름 | 1.6초 + 글자당 70ms, 최대 6초 | 다 쓴 뒤 읽을 시간. 18자 = 2.9초 |
| 대화 순서 | 앞 사람 머무름이 끝나면 다음 사람 | 회의 재연도 같은 규칙(시안 “회의 재연” 무대) |

**회의 재연(2~3번 주고받기) 확인 결과**: 한 사람에 말풍선 하나, 상대의 지난 말은 회색 규칙이면 몇 번을 주고받아도 화면에는 둘까지만 남는다. 세 번 주고받는 시안에서 어색한 곳은 없었다. 회의록에서 자른 문장이 36자를 넘으면 말줄임이 된다. 그래서 재연용 문장은 **36자 안으로 자르는 것**을 권한다.

- **지난 말풍선은 투명도 대신 색을 뺀다.** 처음에는 투명도 50%를 썼다. 그런데 밝은 배경에서 글자 대비가 무너져서 회색 테두리 + 보조 글자색(7.2:1)으로 바꿨다.

### 3.5 움직임

| 동작 | 기본 | 움직임 줄이기 |
|---|---|---|
| 등장 | 지시선이 자라고(160ms) → 탭이 펼쳐지고(160ms, 5계단) → 판이 열림(240ms, 5계단) | 120ms 페이드 |
| 반응 | 튀어나옴(240ms, `--ease-pop`) | 120ms 페이드 |
| 타자 | 28ms/자 + 깜빡이는 커서 | 바로 전체 문장, 커서 없음 |
| 둥실 | 3px, 2.6초 | 없음 |
| 퇴장 | 160ms 페이드 | 120ms 페이드 |

움직임 줄이기는 토큰 값만 바뀐다. 켜는 조건은 두 가지다.

- OS 설정 `prefers-reduced-motion`
- 책상 방과 공유하는 설정 → `html[data-motion="reduce"]`

반대로 `html[data-motion="full"]`이면 OS 설정이 있어도 사용자의 선택을 따른다.

### 3.6 화면 읽기 프로그램

- 화면 밖에 `role="log" aria-live="polite" aria-label="사무실 대화"` 영역을 하나 둔다.
- **다 쓴 문장만** 한 번 넣는다: `메모(기획) → 메시(3D): 원문`. 화면에서는 잘렸어도 로그에는 원문이 들어간다.
- DOM에는 최근 20개만 남긴다.
- 꼬리표와 모니터는 읽어 주지 않는다. 바뀌는 빈도가 높아서다. 대신 에이전트 목록(누르면 이름표·역할이 나오는 곳)의 접근 가능한 이름에 지금 활동을 붙여, 필요할 때 읽게 한다.
- 비공개는 `루프(코더): 비공개 대화`로만 넣는다.
- 말풍선 DOM 자체는 `aria-hidden` 처리하는 것을 권한다. 로그와 내용이 겹쳐 두 번 읽히지 않게 하려는 것이다.

### 3.7 좁은 화면 (≤ 640px)

- 폭은 200px로 줄이되, 글자 크기는 그대로 12px다. 갈무리는 12px 아래에서 획이 깨진다.
- 대화에서는 지금 말하는 쪽만 보인다. 상대의 지난 말풍선은 숨긴다.
- 꼬리표는 아이콘만 보인다. 문구는 에이전트 목록에서 볼 수 있다.

## 4. 모니터 화면 (`screen_work_0..3`)

### 4.1 얼마나 작게 보이나

#16에서 확정된 크기: 0.57 × 0.33 m(aspect 1.7273), 캔버스 584 × 338(1024 px/m).

지금 기본 카메라 기준으로 계산했다(`src/App.tsx`: 위치 (6.6, 6.2, 7.4), 세로 시야각 32°, 화면 높이 900px). 3D 표시 배율(dpr)은 앱과 같게 최대 1.5다.

| 거리 | 1 m가 화면에서 | 모니터 가로 | 무엇이 읽히나 |
|---|---|---|---|
| 기본 카메라 ≈ 14 m | ≈ 109 px | **≈ 62 px** | 바탕 밝기, 에이전트 색, 아이콘 덩어리 |
| 다가간 시점 ≈ 6 m (이슈의 “1/4”) | ≈ 260 px | ≈ 146 px | 활동 문구 48px → **12px = 갈무리 원본 크기** |
| 바로 앞 ≈ 1.4 m | ≈ 1,024 px | 584 px | 이름·시각·경과 시간까지 |

**결론**: 전경에서는 어떤 글자도 읽히지 않는다. 그래서 상태마다 **화면의 밝기 패턴**이 달라지게 설계했다. 그 위에 1/4 거리부터 활동 문구가 또렷해지도록 크기를 맞췄다. 시안 카드마다 1/4과 전경 크기 미리보기가 붙어 있다. 큰 캔버스를 절반씩 줄여 그려 밉맵을 흉내 낸 것이다.

- 에이전트 색은 바탕 틴트(8%), 이름, 진행 띠에만 쓴다. 본문은 아이보리다. 네 색 모두에서 같은 대비를 내기 위해서다.
- 진행 띠는 실제 진행률이 아니다(훅은 도구 이름만 보낸다). 흐르는 3칸은 “움직이고 있다”는 표시다. 그래서 퍼센트처럼 보이는 표현은 피했다.
- 활동 문구와 아이콘은 꼬리표와 같은 표를 쓴다(시안의 표).
- 훅이 보내는 `activity` 이름과 1:1로 맞췄다(#1 결정). 훅은 Bash 명령을 내 PC 안에서 종류로 분류해, 명령 원문 없이 종류 이름만 보낸다.

| activity | 문구 | 언제 |
|---|---|---|
| `edit` | 파일 편집 중 | Edit · Write |
| `read` | 코드 읽는 중 | Read · Grep · Glob |
| `test` | 테스트 실행 중 | Bash → 테스트 |
| `build` | 빌드 중 | Bash → 빌드 |
| `install` | 설치 중 | Bash → 패키지 설치 |
| `git` | 버전 기록 중 | Bash → git |
| `run` | 앱 실행 중 | Bash → 앱·스크립트 실행 |
| `other` | 명령 실행 중 | Bash → 그 밖의 명령 |
| `delegate` | 일 나누는 중 | 하위 에이전트를 띄움 |
| `think` | 생각 중 | 요청을 받은 직후(UserPromptSubmit), 도구를 쓰기 전. 아이콘은 말줄임표 말풍선(#75에서 더함) |

- 표에 없는 `activity`가 오면 문구 “작업 중”과 `cmd` 아이콘을 쓴다(#75). 훅에 새 활동이 생기면 이 표에 먼저 더한다.

- 모니터 문구는 가장 긴 것(“테스트 실행 중”)도 아이콘과 함께 한 줄(48px)에 들어간다.
- 다른 에이전트에게 일을 넘기는 것은 활동 문구가 아니라 대면 대화(말풍선)로 보인다.

### 4.3 구현 메모 (코더에게)

- **그리는 빈도**: 캔버스 텍스처는 바뀔 때마다 GPU로 다시 올라간다(`needsUpdate`).
  - 초당 8번이면 충분하다. 계단식 움직임이 오히려 화면답다.
  - 상태가 그대로면 진행 띠만 다시 그린다.
  - 화면 밖 모니터는 멈춘다.
  - 시안도 125ms 간격으로 그린다.
- **블룸**: 화면 재질은 `toneMapped: false`라서, 블룸 임계값을 넘으면 48px 글자가 번진다. 화면 밝기 상한 토큰 `--screen-glow`(0.85)를 곱하거나, 화면을 블룸에서 빼는 것을 권한다.
- **픽셀 폰트**: 캔버스 글자 크기는 토큰 값(24·48·120) 그대로 쓴다. 정수배가 아니면 획 굵기가 들쭉날쭉해진다.
- **아이콘**: 시안 `ICONS`의 12×12 비트맵이 원본이다. 꼬리표는 SVG(×1), 캔버스는 `fillRect`(×8, ×24)로 그린다. 정수배로만 키운다.
- 퇴근 상태는 빛을 거의 내지 않으므로, 베이크 때 모니터가 책상을 비추던 빛과 어긋나 보일 수 있다. Blender 세션과 확인이 필요하다.

## 7. 폰트

- **갈무리11 Regular·Bold** (`galmuri@2.40.3`, SIL Open Font License 1.1, © Lee Minseo). 책상 방과 같은 버전·같은 두 파일이고, 새로 들이는 폰트는 없다.
- 용량: woff2 Regular 505 KB, Bold 167 KB. Bold는 KS X 1001 한글 2,350자만 들어 있어 작다. 활동 문구와 이름은 모두 이 범위 안이다.
- 오피스는 책상 방 안 iframe으로, 같은 출처에서 열린다(plan 2.1). 그래서 **책상 방과 같은 URL로 서빙하면 브라우저 캐시를 그대로 쓴다.** 방에 들어올 때 폰트를 다시 받지 않게 경로를 맞추는 것을 권한다(코더와 확인).
- 따로 줄이고 싶다면 Regular를 KS X 1001 + ASCII로 부분집합 처리하면 크게 준다. 다만 방문자 쪽지(plan 7)에 드문 글자가 들어올 수 있어 지금은 권하지 않는다.
- 시안 HTML은 열람용으로만 jsDelivr에서 같은 버전을 불러온다.

| 세우는 컷 | 6초 |

- 사건이 생기면 지금 컷이 최소 4초 지난 뒤 끼어든다.
- 타임랩스(#158) 재생 중: 머무는 시간 ÷ 배속, 최소 3초다. ×16에서는 사건 컷만 쓴다.

### 10.3 구도

렌즈는 바꾸지 않는다(세로 화각 32° 그대로). 크기는 거리로만 정한다. 좁은 화각으로 바꾸면 3D가 납작해 보이고 책상 방 카메라와 결이 달라진다.

| 컷 | 카메라 → 보는 점 | 화면 |
|---|---|---|
| 일하는 에이전트(어깨 너머) | 자리에서 등 뒤로 1.4 m · 오른쪽으로 0.8 m, 높이 1.75 m → 머리와 모니터 사이(높이 1.05) | 머리 · 두 손 · 모니터가 한 화면, 머리가 화면 왼쪽 1/3 |
| 일하는 에이전트(얼굴 쪽, 포드 북쪽 메시 · 휴) | 자리 옆 · 위에서: 책상 끝 바깥 1.3 m, 높이 2.0 m → 얼굴(1.15) | 얼굴 화면 · 손 · 모니터 뒷면. 반대편 줄 머리에 가리면 높이를 2.3까지 올림 |
| 메모(머리 자리) | 동쪽 1.6 m · 남쪽 0.6 m, 높이 1.8 → 머리 | 얼굴 · 포드 전체가 뒤에 보임 |
| 회의 | 원 가운데에서 카메라 쪽(남동)으로 4.0 m, 높이 2.6 → 원 가운데(높이 1.0) | 원 지름(2.2 m)이 화면 폭의 60% |
| 탁구 | 탁구대 옆(긴 변 쪽) 3.8 m, 높이 2.2 → 탁구대 가운데 | 두 선수와 공 |
| 오목 | 탁자 옆 2.0 m, 높이 1.8 → 판 | 판과 두 손 |
| 소파 · 커피 · 물 주기 | 대상에서 2.2 m, 높이 1.7 | 상반신 |

- **가는 길**: 1.6초, ease-in-out, 위로 볼록한 곡선(가운데에서 0.6 m 높이)으로 간다. 벽 위 · 방 밖을 지나지 않고, 컷어웨이 벽(#111) 높이 위로만 넘는다. 사물을 뚫으면 곧장 컷(0.3초 페이드)으로 바꾼다.
- **머무는 동안**: 카메라가 아주 천천히 4° 옆으로 흐른다(정지 화면처럼 보이지 않게). 에이전트가 움직이면 보는 점이 따라간다(0.5초 늦게).
- **움직임 줄이기**: 날아가지 않고 0.3초 페이드 컷으로 바꾼다. 흐름도 끈다.

### 10.4 화면 UI

```
데스크톱                                                   (HUD 도크는 오른쪽 아래 그대로)
┌────────────────────────────────────────────────────────────────┐
│ ← 책상으로   (에이전트 목록)                                     │
│                                                                │
│                        3D (둘러보기 중)                          │
│                                                                │
│           ┌──────────────────────────────────────┐   [소리]    │
│           │ ◀  ● 루프 · #182 · 테스트 돌리는 중  ▶ │ ■ │   [타임랩스]│
│           └──────────────────────────────────────┘   [서재]    │
└────────────────────────────────────────────────────────────────┘
```

- **자리**: 화면 아래 가운데, 바닥에서 16 px 위다. 둘러보기 중에는 WASD 안내 자리를 대신한다(안내는 숨김).
  - 옆 패널이 열리면 둘러보기가 멈추므로 겹치지 않는다.
  - 도크와는 가로로 최소 24 px 떨어지게 한다. 화면이 좁아(≤ 900 px) 닿으면 바를 도크 위로 올린다.
- **모양**: 높이 40 px, 최대 폭 480 px, 바탕 `--color-surface` 90%, 1 px 선이다.
  - 가운데는 지금 비추는 에이전트의 색 점 + 이름 + #182 작업 칩 문구이고, 줄어들면 칩부터 줄인다.
  - 회의 컷이면 `회의 · 다섯 명`, 세우는 컷이면 `사무실 전체`다.
- **이전 · 다음**: 양끝의 ◀ ▶ 버튼(32 × 32)이다. 누르면 그 컷으로 가고, 머무는 시간을 처음부터 센다. 이전은 지나온 기록을 따라간다(최근 8컷).
- **멈춤**: 오른쪽 ■ 버튼이다. 누르면 둘러보기가 끝나고 바가 사라진다(WCAG 2.2.2의 멈춤 수단). 이 버튼을 눌렀을 때만 그 탭에서는 다시 자동으로 시작하지 않는다(새로 고치면 초기화).
- **키**: `[` 이전 · `]` 다음 · `Esc` 멈춤이다. ← → 와 WASD는 그대로 자유 시점 입력이라, 누르면 둘러보기가 끝난다.
- **나타남**: 둘러보기가 시작될 때 바가 0.24초에 아래에서 올라오고, 끝날 때 내려간다. 움직임 줄이기면 바로 나타난다.
- **화면 읽기**: `aria-live="polite"`로 컷이 바뀔 때 "루프, 테스트 돌리는 중"을 읽는다. 5초 안에 다시 바뀌면 읽지 않는다.

**휴대폰 (≤ 640 px)**
- 바는 아래 가운데, 도크 줄 위 8 px다. 폭은 화면 − 32 px이고, ◀ ▶는 44 × 44다.
- **스와이프**: 둘러보기 중에 3D 위에서 가로로 60 px 넘게 빠르게(0.3초 안) 밀면 다음(왼쪽으로 밀기) · 이전(오른쪽으로 밀기)이다.
- 그 밖의 터치(탭, 느린 끌기, 두 손가락)는 둘러보기를 끝내고 자유 시점이 된다.
- 시작 대기 시간은 데스크톱과 같다(45초).

### 10.5 판정
- 기본 카메라에서 45초 기다린 뒤 3분 녹화한다.
  - 일하는 에이전트가 먼저 나오는지
  - 같은 에이전트가 잇달아 나오지 않는지
  - 4컷마다 세우는 컷이 나오는지
- 컷마다 위 구도표와 나란히 놓고 봅니다(다섯 에이전트 모두, 회의 · 탁구 · 오목).
  - 머리 · 손 · 모니터(또는 소품)가 한 화면에 드는지
  - 가는 길에 벽 · 사물을 뚫지 않는지
- 입력 한 번에 그 자리에서 멈추는지, ◀ ▶ · `[` `]` · 스와이프 · ■가 되는지 확인합니다.
