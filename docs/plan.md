# 에이전트 오피스 설계

> 2026-11-07 시작. 방향은 정해졌고, 세부는 단계를 밟으며 채운다. 결정이 생기면 맨 아래 결정 기록에 남긴다.

## 1. 무엇을 만드나

내 AI 에이전트들(Claude Code 세션)이 일하는 모습을 방문자가 **실시간으로** 보는 사무실. 에이전트가 쉬는 시간에도 볼거리가 있어서 다시 올 이유가 있고, 에이전트가 남긴 작업 문서 가운데 **민감하지 않은 것**은 방문자도 읽을 수 있다.

참고한 것: 픽셀 사무실 시각화들([pixel-agents](https://github.com/pablodelucca/pixel-agents), [Claude-Office](https://github.com/W17ant/Claude-Office), [pixel-office](https://github.com/Sebaspelusa/pixel-office), [agent-virtual-office](https://github.com/KbWen/agent-virtual-office)), 3D [CLAW3D](https://www.claw3d.ai/). 대부분 훅·로그를 엿보는 "관찰자"다. 여기는 관찰에 더해 **방문자와 주고받는 공간**을 지향한다.

## 2. 전체 구조

```text
 내 에이전트들 (Claude Code 세션: 여러 PC·클라우드)
   │ ① 훅이 상태 신호를 보냄 (도구 이름 수준, 내용은 안 보냄)
   ▼
 서버 함수 /api/events            ② 비밀 토큰 확인, 공개 등급 판정, 민감 정보 제거
   ▼
 Supabase (Postgres + Realtime)    ③ 새 상태·이벤트를 구독 중인 브라우저로 즉시 전달
   ▼
 방문자 브라우저 = 사무실 화면     ④ 상태에 맞춰 에이전트 애니메이션, 문서·쪽지 열람
```

- 배포는 Vercel(정적 사이트 + 짧은 서버 함수). 함수는 오래 연결을 붙잡지 못하므로 실시간 전달은 Supabase Realtime이 맡는다.
- **쓰기는 항상 서버 함수를 거친다.** 브라우저는 공개 등급 데이터만 읽기 전용으로 구독한다(RLS).
- 화면 기술은 rowansong.dev와 같게(React + React Three Fiber, Blender 모델 + 라이트 베이킹) 맞춰, 책상 방에서 넘어오는 연출을 자연스럽게 한다.

### 2.1 rowansong.dev와의 관계: 허브와 방

- rowansong.dev의 책상 방은 **허브**, 프로젝트 하나가 **방** 하나. 이 오피스가 첫 번째 방이다.
- 책상의 **잠긴 모니터 = 이 방의 문.** 방탈출 코드로 열리고, 누르면 카메라가 모니터 화면 속으로 파고들어 이 방으로 넘어온다. 모니터에서 오피스를 재생하지는 않는다.
- **이동 방식(결정)**: 오피스는 책상 방 페이지 안에서 iframe으로 띄우고, `history.pushState`로 주소만 `/rooms/office`로 바꾼다. 이 저장소는 따로 배포하고, rowansong.dev가 리라이트로 같은 출처에 붙인다(방탈출 진행·소리 설정을 localStorage로 공유).
- **나가는 입구는 넷, 애니메이션은 하나**: 브라우저 뒤로가기(`popstate`), Esc, 어디서나 같은 자리의 "← 책상으로", 방 안의 출입문. 모두 같은 퇴장 애니메이션을 부르므로 뒤로가기도 끊기지 않는다. 오피스 안에서 나가기를 누르면 부모(책상 방)에 메시지를 보내 연출을 맡긴다.
- 공유 링크로 `/rooms/office`에 바로 온 사람에게는 오피스부터 보여 주고 뒤에서 책상 방을 준비한다.

**방 주소와 메시지 약속 (2026-11-08, 두 저장소 문서에 같은 글)**

**주소**

| 주소 | 누가 서빙 | 뭐가 보이나 |
|---|---|---|
| `/rooms/office` (정확히 이 경로, 끝 `/`만 허용) | 책상 방 앱(SPA 폴백) | 책상 방 + 오피스 iframe. 방문자가 보는 주소는 이것뿐 |
| `/rooms/office/app/` (그 아래 전부) | 오피스 배포(리라이트) | 오피스 앱 자체. iframe의 `src`(`…/rooms/office/app/?embed=room`). 직접 열면 단독 오피스: "← 책상으로"가 `https://rowansong.dev/`(책상 방 루트)로 간다 |

- 책상 방 라우터는 `/rooms/office/app`(과 그 아래)를 방 경로로 보지 않는다. 정확히 `/rooms/office`만 방이다.
- 리라이트 초안(배포 때 `vercel.json`, 지금은 적용 안 함): **`/rooms/office/app/(.*)` → 오피스 배포가 먼저**, 그다음 책상 방 SPA 폴백(`/((?!api/).*)` → `/index.html`). 순서가 바뀌면 오피스 앱 주소가 책상 방으로 먹힌다.
- 오피스는 `OFFICE_BASE=/rooms/office/app/`로 빌드한다(에셋·`/api/*` 모두 이 base를 따른다).

**메시지(postMessage)**: 봉투 `{ ns: 'rowansong.room', v: 1, type, ...fields }`. 그 밖의 것은 무시한다.

| type | 방향 | 필드 | 뜻 |
|---|---|---|---|
| `ready` | 오피스 → 책상 | `room: 'office'` | 방 모드의 오피스는 **카메라를 출입문 앞(문 화면 중심 + 법선 방향 2.4 m)에 둔 채** 모델을 불러와 첫 프레임을 그린 뒤 보낸다. 인터레이스 틈으로 호박색 `DESK.LNK`가 보이게 하기 위해서다. 책상은 이 신호가 올 때까지 대기 화면을 보이고(시간 초과 시 실패 화면), 오면 CRT 전환을 시작한다 |
| `exit` | 오피스 → 책상 | `room: 'office'`, `via: 'door' \| 'esc'` | 방문자가 안에서 나가기를 요청했다(출입문 클릭, Esc). 오피스는 곧바로 자기 쪽 연출(X1)을 시작하고, 책상은 나가기 연출을 한다 |
| `entered` | 책상 → 오피스 | 없음 | 들어가기 연출의 CRT 시작(C0): 오피스는 문 앞에서 물러나기 시작한다. 바로 접속한 방문자에게는 `ready`를 받는 즉시 보낸다. 5초 안에 안 오면 오피스가 스스로 물러난다 |
| `leaving` | 책상 → 오피스 | 없음 | 나가기 시작(0 ms): 오피스는 열린 패널을 닫고 입력을 무시하며 문 화면으로 파고든다(X1, 700 ms). 책상은 응답을 기다리지 않고 450 ms 뒤 CRT 되감기(X2)를 시작한다 |

허용 origin
- 오피스: `event.source === window.parent` **이고** `event.origin`이 허용 목록(자기 origin + `VITE_ROOM_PARENT_ORIGINS`, 쉼표 구분, 기본 `https://rowansong.dev`)에 있을 때만 받는다. 부모에게는 명시한 targetOrigin(`'*'` 금지)으로 보낸다: 부모 origin(`location.ancestorOrigins[0]`, 없으면 `document.referrer`의 origin)이 허용 목록에 있을 때만, 아니면 보내지 않는다.
- 책상: `event.source === iframe.contentWindow` **이고** `event.origin`이 오피스 origin(`VITE_OFFICE_URL`을 현재 주소 기준으로 푼 값; 배포에서는 같은 출처)일 때만 받는다.


## 3. 에이전트

- 에이전트 = 역할별 Claude Code 세션. 그 역할이 사무실의 자리와 이름표가 된다.
- **4명**(2026-11-08 결정): 기획(설계·이슈·결정), 3D(Blender 에셋), 디자인(시각·UI), 코더(프론트·백엔드). 작업 자리 4개와 같다.
- 세션 ↔ 에이전트 연결: 훅이 보내는 세션 ID와 작업 폴더로 매핑(설정 파일). 처음 보는 세션은 "임시 직원"으로 표시. 각 세션이 띄우는 하위 에이전트는 자리를 따로 받지 않고 그 에이전트의 활동으로 묶는다.
- 이름·외형: 디자이너가 역할별로 제안 → 내 결재(6.5절) → 3D가 모델링.

## 4. 상태 네 가지

| 상태 | 언제 | 보이는 모습 |
|---|---|---|
| 작업 중 | 훅 신호가 들어오는 동안 | 자기 책상에서 타이핑. 머리 위에 활동("파일 편집 중", "명령 실행 중", "테스트 실행 중"). 다른 에이전트에게 일을 넘기면 서류를 들고 이동 |
| 정리 중 | 세션이 끝난 직후 | 화이트보드로 가서 작업 카드를 붙임 |
| 휴식·놀이 | 신호가 없을 때(대부분의 방문 시간) | 탁구, 보드게임, 커피 머신 수다, 화분 물 주기, 낮잠 |
| 퇴근 | 밤, 또는 오래 쉰 뒤 | 불이 하나씩 꺼지고 한 명만 야간 당번 |

- **놀이는 결정적 시뮬레이션**: 현재 시각(분 단위)과 에이전트 목록을 씨앗으로 "지금 누가 무엇을 하는지"를 계산한다. 모든 방문자가 같은 장면을 보고, 서버가 필요 없다.
- 작업 신호가 오면 놀던 에이전트가 하던 걸 내려놓고 책상으로 뛰어간다. "진짜 지금 일한다"를 느끼게 하는 순간.

### 4.1 이동과 대면 대화

- **에이전트는 떠 있는 머리 + 떠 있는 두 손이다.** 몸통·다리·팔이 없다. 머리가 바닥 위를 미끄러지듯 떠다니고(아래로 에이전트 색 호버 빛), 두 손은 머리를 살짝 늦게 따라오며 따로 움직인다(타자, 소품 들기, 손짓). 걷기 동작이 없어 어디로든 자연스럽게 가지만, **가구는 통과하지 않는다.** 형태·치수는 #28(디자인), 모델은 #27.
- **순간이동 없음.** 모델에 들어 있는 동선 지점(`nav_*`: 작업 자리, 화이트보드, 게시판, 책장, 커피, 탁구대 양끝, 소파, 보드게임, 출입문, 대화 지점)과 통로 노드(`nav_hall_*`)를 그래프로 이어, 최단 경로를 따라 간다. 출발할 때 살짝 떠오르고, 방향을 틀 때 몸을 기울이고, 도착하면 그 지점이 정한 방향으로 돈다.
- **메시지 = 직접 만나서 대화.** 한 에이전트가 다른 에이전트에게 일을 넘기거나 물어보면(훅 신호), 보낸 쪽이 받는 쪽 책상 옆(`nav_desk_side_*`)으로 가거나, 둘이 대화 지점(`nav_meet_*` 한 쌍, 0.8 m 간격)으로 모여 **마주 보고** 말풍선을 주고받은 뒤 각자 자리로 돌아간다.
- 놀이도 같은 규칙: 탁구는 양끝 지점, 보드게임은 두 스툴, 커피는 카운터 앞.

## 5. 신호와 데이터

### 5.1 훅이 보내는 것

훅은 이벤트마다 **자리 번호(0..3), 신호 종류, 활동 종류** 셋만 보낸다. 세션 ID·이름·작업 폴더·명령 원문·도구 입력과 출력은 PC 밖으로 나가지 않는다. 자리는 세션 이름(`/rename`)으로 PC 안에서 정하고, Bash 명령도 PC 안에서 종류로 나눈다. 규칙과 설치 방법은 `hooks/README.md`에 있다(#1).

| 훅 | 보내는 것 | 사무실 상태 |
|---|---|---|
| SessionStart | `start` | 출근(쉬는 중) |
| UserPromptSubmit | `activity: think` | 작업 중 · 생각 중 |
| PreToolUse | `activity`: edit · read · delegate, Bash는 test · build · install · git · run · other | 작업 중 · 활동 문구 |
| Stop(턴 끝) | `stop` | 정리 중 → 작업 일지 초안(6절) |
| SessionEnd | `end` | 퇴근 |
| PostToolUse / PostToolUseFailure(test·build 명령) | `result` + `ok`(성공/실패 하나) | 책상 LIVE 소품: 신호등·링 조명(#44). 어느 이벤트가 불렸는지만 보고, 출력은 읽지 않음 |

- 하위 에이전트의 도구 호출은 부모 세션(같은 자리)의 활동으로 센다.
- 서버는 마지막 신호만 기록한다. 신호가 끊긴 뒤의 판단은 페이지가 타임스탬프로 한다. 작업 중에 3분 동안 신호가 없으면 쉬는 중, 정리 중은 2분 뒤 쉬는 중, 2시간 동안 신호가 없으면 퇴근이다.

### 5.2 테이블 (초안)

| 테이블 | 내용 | 방문자 |
|---|---|---|
| `agents` | 이름, 역할, 자리, 외형 | 읽기 |
| `agent_status` | 에이전트별 현재 상태·활동·갱신 시각 | 읽기(Realtime) |

| `docs` | 문서(6절): 종류(`plan`·`minutes`·`decision`·`report`·`worklog`), 프로젝트, 파일철(이슈 번호), 제목·요약·본문(마크다운), 참여 에이전트, 원천(종류·주소), 등급, 승인 상태, 시각 | 공개 문서는 전체, SECRET은 표지만 |

| `visitor_notes` | 방문자 쪽지·응원 | 읽기, 쓰기는 서버 함수로 |

## 6. 문서: 기획서·회의록·보고서와 공개 등급

사무실의 문서는 에이전트들이 실제로 일한 흔적이다. 무엇을 왜 하기로 했고(기획서), 어떻게 의논했고(회의록), 무엇을 해냈는지(보고서)가 쌓인다. 방문자는 공개 등급만큼 읽고, 못 읽는 문서도 **SECRET 문서**로 존재는 보인다.

### 6.1 문서 종류와 폴더

| 종류 | 무엇 | 원천 | 쓰는 쪽 | 사무실에서 |
|---|---|---|---|---|
| 기획서 `plan` | 무엇을 왜 만드나, 범위·하지 않을 것·완료 기준 | GitHub 이슈 본문(이슈 폼 = 지시서) | 기획 에이전트 | 화이트보드 "진행 중", 서재 |
| 회의록 `minutes` | 에이전트끼리 주고받은 협의, 결정, 후속 | 이슈 댓글 중 `🗂 에이전트 간 협의 기록` | 그 이슈를 맡은 에이전트(기획 결정은 기획) | 회의 재연 장면, 서재 |
| 결정 `decision` | 결정 하나와 이유 | 설계 문서 결정 기록 표의 한 줄, 회의록의 **결정** 줄, 결재 결과 | 기획 에이전트 | 화이트보드 "최근 결정" |
| 보고서 `report` | 무엇을 했고 무엇을 확인했나(전후 그림) | 머지된 PR 본문(PR 템플릿의 확인한 것 표·스크린샷) | 작업한 에이전트 | 화이트보드 "완료", 서재 |
| 작업 일지 `worklog` | 세션 하나의 목표·한 일·결정·다음 | Stop 훅 작업 카드 | 그 세션 | 에이전트를 눌렀을 때 "오늘 한 일" |

- **프로젝트 폴더 → 파일철 → 문서.** 맨 위는 프로젝트 폴더(저장소 하나 = 폴더 하나: `agent-office`, `rowansong.dev`, …). 그 안에 파일철(이슈 하나), 그 안에 기획서 → 회의록들 → 보고서. 방문자는 파일철 하나를 열어 "어떻게 정해지고 만들어졌는지"를 순서대로 읽는다. 회사 업무는 이름 없이 "비공개 프로젝트" 폴더 하나로 모인다.
- 주간 보고서(나중): 한 주 동안 닫힌 파일철을 기획 에이전트가 한 장으로 정리. 정해진 시각에 도는 작업.

### 6.2 원본은 GitHub, 서버는 사본

- 사람(나)이 이미 보는 곳이 GitHub 이슈·PR이므로 문서의 **원본은 GitHub**에 둔다. 에이전트는 지금처럼 이슈·댓글·PR을 쓰기만 하면 문서가 생긴다. 같은 내용을 두 번 쓰지 않는다. 저장소가 곧 프로젝트 폴더다.
- 저장소마다 GitHub Action 하나: 이슈 열림·수정·닫힘, 협의 기록·결재 요청 댓글, PR 머지 → `/api/docs`(비밀 토큰). 서버가 등급 판정·필터 후 `docs`에 넣거나 갱신한다(원천 주소로 같은 문서인지 판별).
- 작업 일지만 원천이 훅(Stop)이다. GitHub에 남지 않는 세션 단위 기록이기 때문.
- **주인과 협업자가 쓴 것만 문서가 된다(#38).** 공개 저장소라 누구나 이슈·댓글을 쓸 수 있으므로, `author_association`이 OWNER·COLLABORATOR인 것만 받는다. 결재(`🖊`·`✅`)는 주인 계정이 쓴 것만 받는다. Action과 서버가 각각 거른다. 방문자의 의견은 GitHub이 아니라 사무실 게시판(`visitor_notes`, 서버 함수 + 필터, 7절)으로만 받는다.
- **형식이 곧 문서 틀이다.** 이슈 폼, PR 템플릿, 협의 기록·결재 요청 댓글 형식(제목 + 표 + 결정·후속)을 서버가 읽어 문서로 바꾼다. 형식을 바꿀 때는 읽는 쪽도 같이 고친다.

### 6.3 공개 등급과 SECRET 문서

등급은 저장소 허용 목록으로 정한다. 문서 종류와 상관없이 같은 규칙.

| 등급 | 대상 | 방문자에게 |
|---|---|---|
| `public` | 공개 저장소(이 저장소) | 자동 공개. GitHub 원문 링크도 함께 |
| `review` | 비공개 개인 저장소(rowansong.dev 등)와 목록에 없는 곳(기본값) | 내가 결재(6.5절)하기 전엔 **SECRET 문서**. 결재하면 공개(원문 링크는 없음) |
| `private` | 회사 업무 등 | 언제나 **SECRET 문서**. Action을 달지 않고 훅도 내용 없이 보냄. 내용은 서버에 올리지 않음 |

- **SECRET 문서**: 방문자가 "아, 비밀 문서구나"를 알게 한다. 서재에 SECRET 도장이 찍힌 책으로 꽂히고, 열면 표지(종류·프로젝트 폴더·날짜·참여 에이전트)와 검게 지운 본문 자리만 보인다. `private`는 제목과 폴더 이름도 지운다. `review` 문서가 결재되면 도장이 떨어지며 정식 문서로 바뀐다(작은 연출).
- 서버가 한 번 더 거른다: 파일 경로, 이메일, 토큰·키 모양 문자열, 금지어 목록(사내 이름 등, 비공개 설정). 걸린 부분은 가리고 그 문서를 SECRET(`review`)으로 내린다.

### 6.4 사무실에서 보이는 방식

- **서재(책장)**: 칸 = 프로젝트 폴더, 책 한 권 = 파일철(책등에 이슈 번호·제목, SECRET이면 도장). 누르면 HTML 문서 뷰어(목차: 기획서 → 회의록 → 보고서).
- **화이트보드**(`surface_whiteboard`): 세 칸(진행 중 / 검토 / 완료)에 이슈 카드, 옆에 최근 결정 3개.
- **회의 재연**: 새 회의록이 들어오면 참여한 에이전트들이 하던 걸 멈추고 대화 지점(`nav_meet_*`)으로 모인다.
  - **회의록 표 한 줄 = 대사 한 번.** 협의 기록 표가 이미 "누가 누구에게 무엇을"이므로 대사를 따로 쓰지 않는다. 보낸 쪽이 말하고 받는 쪽이 마주 보고 듣는다.
  - 말풍선엔 내용 칸의 첫 문장만(약 40자, 넘으면 말줄임). 전문은 말풍선을 누르거나 끝난 뒤 문서 뷰어에서.
  - 마무리: **결정** 줄은 기획 에이전트가 화이트보드에 카드로 붙이는 동작으로, **후속**은 맡은 에이전트가 자기 자리로 가는 것으로 보여 준다. 끝나면 서재에 책이 꽂힌다.
  - 표에 사람(나)이 있으면 그 대사는 출입문 화면에 `ROWAN` 메시지로 뜬다(사무실에 사람 모델은 두지 않음).
  - SECRET 회의록도 회의는 열린다. 같은 에이전트들이 모여 말풍선을 주고받지만 글자가 검은 줄(`████ ██`)로 나온다. 비밀 회의를 엿보는 재미.
  - 새 회의록이 없을 때는 지난 회의록 하나를 시각 기반으로 골라 다시 보여 줄 수 있다(놀이와 같은 씨앗 규칙이라 모든 방문자가 같은 장면).
- **에이전트를 누르면**: 이름표·역할과 오늘 쓴 문서 제목들.
- **게시판**(`surface_bulletin`)은 방문자 쪽지 전용(7절). 에이전트 문서와 섞지 않는다.
- rowansong.dev 단말기 OS의 '작업 일지' 앱이 같은 `docs`를 2D 목록으로 보여 준다.

### 6.5 결재: 내 확인이 필요한 일

에이전트가 내 확인을 받아야 할 때 **결재 요청**을 올린다. 사무실 결재함에 쌓이고, 내가 로그인해 들어오면(6.6절) 거기서 결재한다. 터미널에서 직접 답하는 지금 방식도 그대로 된다. 결재는 하나 더 생기는 통로다.

| 종류 | 예 | 결재 결과 |
|---|---|---|
| 문서 공개 | `review` 문서(SECRET)를 공개할지 | 공개 / 고쳐서 공개 / 계속 SECRET |
| 결정 요청 | 기획이 정해 달라는 질문(선택지 + 추천안) | 선택지 하나, 또는 의견 |
| 산출물 확인 | 시안·모델 확인, PR 합치기 | 승인 / 반려(사유) |

- **원본은 역시 GitHub.** 요청은 이슈 댓글 `### 🖊 결재 요청`(종류, 선택지 목록, 추천, 기한 없음) 형식. Action이 `approvals`로 올린다. 내가 결재하면 서버가 같은 이슈에 `### ✅ 결재` 댓글(결과·의견)을 단다. 이력이 GitHub에 남고, 결정 요청의 결과는 결정 문서(`decision`)가 된다.
- **결재 훅(에이전트 쪽)**: 세션 시작·사용자 입력 때 도는 Claude Code 훅이 그 세션 몫의 새 결재 결과를 문맥에 넣어 준다. 결재를 기다리는 에이전트는 막히지 않은 다른 일을 하다가, 결과가 오면 이어 간다.
- **사무실 연출**: 결재를 기다리는 에이전트는 결재함 옆을 서성인다(상태 "결재 대기"). 방문자에게는 결재함에 "결재 대기 N건"과 SECRET 서류만 보인다. 내가 결재하면 도장 소리와 함께 그 에이전트가 자리로 돌아간다.
- **하지 않는 것**: Claude Code의 도구 권한 묻기(명령 실행 허용 등)는 결재로 넘기지 않는다. 공개 웹사이트에 내 PC의 명령 실행을 허락하는 통로가 생기면 위험이 너무 크다. 결재는 GitHub 댓글로 남는 결정·공개·확인만.

### 6.6 주인 로그인

- 방문자는 로그인 없이 구경한다. **나(주인)만 로그인**: Supabase Auth의 GitHub 로그인 + 허용 목록(내 GitHub 계정 ID 하나). 로그인 입구는 눈에 띄지 않게(예: 출입문 화면 구석, `/rooms/office?owner`).
- 주인일 때만: 결재함 열기·결재, `review` SECRET 문서 본문 읽기(`private`는 서버에 없음), 문서 숨김.
- 서버(결재 처리, 숨김)는 로그인 토큰을 확인하고 주인 ID가 아니면 거절한다. 화면에서 버튼을 숨기는 것만 믿지 않는다(RLS도 주인 전용).
- 내가 접속하면 에이전트들이 알아본다(인사·자세). 방문자에게 "주인 접속 중"을 보일지는 9절 열린 질문(기본: 안 보임).

### 6.7 작업 이력 재생: 타임랩스 (#76)

프로젝트가 **처음부터 지금까지 어떻게 만들어졌는지**를 사무실에서 다시 재생해 본다.
- 커밋 하나, 작업 하나가 타임라인의 점 하나다.
- 시간을 옮기면 사무실이 그 시점 모습이 되고, 에이전트들이 그 일을 다시 해 보인다.
- 실시간(지금 일함, 5절)과 문서(6.1~6.6)에 이어, 같은 일을 **시간 축**으로 보는 창이다.

**단위**
- 프로젝트(저장소) 하나 = 타임라인 하나. 서재의 프로젝트 폴더(6.1)와 같은 단위다.
- 모든 프로젝트를 한 줄에 합친 **전체** 타임라인도 둔다. 방 사이를 오가며 만든 흐름이 한눈에 보인다.
- 기간은 첫 커밋부터 지금까지 전체다. 최근 것만 자르지 않는다.

**점(이벤트)과 장면**

| 점 | 원천 | 재생 장면 |
|---|---|---|
| 기획서 | 이슈 열림 | 메모가 화이트보드 "진행 중"에 카드를 붙인다 |
| 작업 | dev에 들어간 커밋(squash 하나 = PR 하나). 그 전의 직접 커밋도 하나씩 | 맡은 에이전트가 자리에서 일한다(모니터에 작업 중). 끝나면 카드가 "완료"로 가고, 보고서 책이 서재에 꽂힌다 |
| 회의록 | `🗂 협의 기록` 댓글 | 회의 재연(6.4)을 짧게 |
| 결재 | `🖊` 요청 / `✅` 결과 | 결재함에 서류가 쌓이고, 결재되면 도장 |
| 결정 | 결정 기록 표의 줄, 회의록의 결정 줄 | 화이트보드 "최근 결정" 메모지 |
| 배포 | main에 들어간 커밋 | 사무실 전체가 한 번 밝아진다. 출입문 화면에 배포 표시 |

- **누가 했나**
  - 이슈의 "누가 하나" 칸을 따르고, 그 이슈를 닫은 커밋도 같은 에이전트로 본다.
  - 역할이 나뉘기 전 커밋(rowansong.dev 초기 등)은 `agent: null`("역할 분담 이전")이다. 어떻게 보일지는 디자인이 정한다.
- **그 시점의 사무실은 다시 만든다.** 화이트보드 카드, 서재 책 수, 결재 대기는 그 시각까지의 점을 차례로 접어서 만든다. 막대를 뒤로 끌면 책이 줄고, 앞으로 끌면 다시 늘어난다.
- 모델·소품은 지금 것을 그대로 쓴다. 그 시점에 아직 없던 사물을 지우는 데까지는 하지 않는다.

**재생**
- 화면 아래 타임라인 막대가 있다. 점은 에이전트 색, 모양은 점 종류다. 위에는 날짜 눈금이 있다.
  - 조작: 드래그, 재생·멈춤, 속도(×1 · ×4 · ×16), 이전·다음 점.
- **빈 시간은 줄인다.** 실제 시각이 아니라 점 순서로 재생한다(×1 = 점 하나에 약 3초). 하루를 넘는 공백은 1초짜리 날짜 넘김으로 보여 준다. 지금 두 저장소 합쳐 약 90점이라, ×1로 전체가 5분 안쪽이다.
- **재생 모드 동안 멈추는 것**: 실시간 상태와 놀이. 화면에 "기록 재생 중"과 그 시점 날짜를 띄운다.
  - 실시간 신호가 들어오면 막지 않고 "지금 ○○가 일하는 중 → 실시간으로" 표시만 한다.
  - 끝나거나 나가면 지금(실시간)으로 돌아온다.
- **들어가는 곳**: 사무실 안 진입 사물(디자인이 정함, 필요하면 Blender), HUD 버튼, 그리고 문서 뷰어 파일철의 "이 일의 이력 재생"(그 이슈 기간만).
- **공유 주소**: `?replay=<프로젝트|all>&t=<시각>`. 그 시점부터 열린다.
- **2D 대체**: 같은 점을 목록으로 보여 준다(날짜 · 에이전트 · 종류 · 제목 · +/− 줄). 키보드와 화면 읽기 프로그램용이고, 휴대폰에서도 이 목록이 기본이다.

**공개 규칙**: 6.3과 같은 등급을 쓴다.

| 등급 | 점에 담는 것 |
|---|---|
| `public` | 날짜, 제목(커밋·이슈 제목), 바뀐 줄 수(+/−), 파일 수, 이슈·PR 번호, 에이전트. GitHub 링크 |
| `review` | 결재 전에는 **SECRET 점**(제목은 검은 줄, 날짜 · 에이전트 · 크기만). 결재되면 제목 공개(링크 없음) |
| `private` | 모으지 않는다. 점도 눈금도 없다. 타임라인은 허용 목록의 프로젝트 세션만 담는다(9절 10, 2026-11-08 결재) |

- 코드 내용, diff, 파일 경로는 어느 등급이든 보내지 않는다. 제목도 6.3의 서버 필터(경로 · 이메일 · 키 모양 · 금지어)를 거친다.

**데이터 통로**
- 원본은 GitHub이다.
- 이슈 · 협의 기록 · 결재 · 머지된 PR은 이미 6.2 문서 통로로 들어온다. 그대로 쓰고, 새로 필요한 것은 **커밋과 배포(push)**뿐이다.
- **백필**: 지난 이력은 한 번 전체를 긁는 스크립트로 넣는다(저장소마다, 다시 돌려도 같은 결과).
- **이후**: 저장소 Action이 dev · main push를 받아 새 점을 올린다.
- 서버는 `timeline` 테이블 하나다. 점의 키는 원천 주소(커밋 sha, 댓글 ID)라 두 번 들어와도 하나로 남는다.
- **배포 전**에는 백필 스크립트가 만든 JSON 사본으로 개발한다. Action과 테이블은 보류 중인 배포 때 함께 켠다.
- 점 형식, 귀속 규칙과 예외 표, 거름 세부: `docs/timeline.md` (#81).

## 7. 방문자 상호작용

- 에이전트를 누르면 이름표, 역할, 오늘 쓴 문서(6.4절)
- 서재·화이트보드에서 공개 문서 읽기(파일철 단위), 프로젝트별로 모아 보기, 회의 재연 구경
- 놀고 있는 에이전트에게 간식·응원 → 반응(표정·짧은 대사)
- 에이전트에게 아이디어 쪽지 남기기 → 사무실 게시판. 욕설·음란어 필터와 도배 제한은 rowansong.dev 방명록과 같은 방식
- 지금 같이 보고 있는 방문자 수(Realtime presence), 다른 방문자의 간식 주기가 실시간으로 보임

## 8. 단계

1. **신호 통로**: 훅 스크립트 → `/api/events` → Supabase → 실시간 구독. 결과물: 오피스 페이지에 "지금 일하는 에이전트" 실시간 목록
2. **문서 체계**(6절): `docs`·`/api/docs`·GitHub Action(이 저장소부터) → 2D 문서 뷰어(폴더·파일철, SECRET 표지) → 주인 로그인·결재(6.5·6.6절) → 서재·화이트보드·회의 재연 → Stop 훅 작업 일지
3. **사무실 공간**: Blender 모델 + 라이트 베이킹(`assets/blender/office.py` 시험판에서 출발), 상태 네 가지 애니메이션, 시각 기반 놀이
4. **방문자 상호작용과 문**: 쪽지·간식·응원, presence. 책상 방의 문(잠긴 모니터)으로 들어오고 나가는 연출
5. **작업 이력 재생**(6.7절): 백필 스크립트 · 점 데이터 → 2D 목록 → 타임라인 막대 · 시점 복원 → 장면 연출 → push Action(배포 때)
